## 一、路线转折点（2026-09-14）

### 用户决策：放弃自发认识，转向现代数学架构

旧系列 6 个版本（v7→v8.3）证明：让模型从算术事实自己归纳数轴结构**能走但极慢**，
且宽度墙是架构性的（数据铺多宽墙就多高）。用户决策全面转向：

> "现代数学已经对数字有了集合方式的现代描述，我们应该从集合、群等现代数学认知
> 开始训练，不要再用自发认识训练，那样效率太低。"

### 新路线核心思想（用户提出，逐步澄清）

1. **中英文 + 数学符号三形式**。数学符号是**逻辑本体**（枢轴语言 pivot language），
   中英文是**交互界面**——训练目标是让中英文的潜空间与数学符号的潜空间**对齐**
   （用户原话："让中英文命中潜空间能和潜空间的数学符号的潜空间对齐"）
2. **先给定义和公理，实例走思维链套用定义公理得出结果**，训练泛化能力
3. 用户最初设想 encoder-decoder 双塔互转；经讨论确认其真实意图就是枢轴对齐，
   **decoder-only + 往返对齐数据**即可实现（65M~130M 劈两塔容量不够）
4. 加法训练必须是思维链：**先知道每个数位代表的意义，然后数位对齐，
   从最低位加起，满 10 进位（减法借位）**（用户设计，继承旧系列竖式显式化经验）

### 方案审核（我方提出 4 个潜在问题，用户逐条回应）

| 问题 | 结论 |
|---|---|
| 表面捷径风险（三形式配对可能只学模板互译） | 缓解：多中文表述配对 + 组合泛化测试；用户补充：**加代数形式 `a∈ℕ. s(a)=a+1`** 强化抽象 |
| 符号 BPE 切分未知 | 预检先行（我来设计） |
| 4 层深度不够 | **用户拍板升 8 层**（~72M），要求全方面评估报告 |
| 三形式配比 | 符号 50% / 中文 25% / 英文 15% / 对齐 10% |

用户追问"模型知道 + 号的意义吗"——回答：不知道，`+` 的意义 = 它在所有样本里的
**共同变换角色**，公理（`a+0=a`、`a+s(b)=s(a+b)`）把这个角色显式定义出来。
这正是公理化数据的价值。

### LaTeX 之辩（用户两次追问）

用户问是否应该一开始就教 LaTeX。我方论证：LaTeX 是排版指令不是数学本体，
token 效率低 60%，v1 内容（ℕ+加法+序）Unicode 完全够用；**后加 LaTeX 本身
是检验潜空间对齐真伪的最强实验**（对齐若真，加第四种表面形式应该很快）。
用户接受：v1 用 Unicode，LaTeX 留作后续对齐层语言。

### v1 定案

- 范围：ℕ + 加法 + 序（负数/ℤ 留 v2，一次验证一个方法论变量）
- 挖洞协议：删末位 7 的 1~4 位数全部实例（9 种写法），保留公理文本
- 先 5 万条小规模验证，通过后用户租算力全量
- 评估脚本训练前备好（旧系列教训：训完没判据 = 白训）

2. MAX_NEW=160 截断加法 CoT → E2 首跑报 0%，实为脚本 bug（与旧系列

**最终成绩**：

| 测试 | 分数 | 意义 |
|---|---|---|
| E1-L1 训练内后继 | 100% | 基础能力 |
| **E1-L2 挖洞后继 `s(7777)`** | **100%** | **真泛化**（训练删光末位 7 实例，靠公理答对） |
| E1-L3 五位数后继 | 0% | `99779`→`9979` 丢位 |
| E2-L1 训练内加法 CoT | 83.3% | 竖式算法执行 |
| **E2-L2 挖洞加法** | **86.7%** | 算法泛化到洞内数 |
| E2-L3 五位数加法 | 0% | `11962`→`1192` 丢位 |
| E3 跨形式（中↔符↔英） | 0% | 训练无混合任务样本（数据缺口） |
| E4 组合泛化 `s(s(a))` | 符号 60% / 中文问 0% | 复合形式训练不足 |
| **E6 序关系（三层）** | **100%** | **序公理五位数外推成功** |

### v1 核心结论

1. **公理化路线核心假设验证通过**：挖洞 100% = 模型学会"套公理"而非查表

2. **序公理宽度外推 100%**：公理化数据突破宽度墙的直接证据
3. 失败项全部可归因于数据缺口，非路线缺陷

## 三、五位数丢位问题深挖（2026-09-15 ~ 09-17）

### 根因诊断

失败样例精确形态：`11962` 被抄成 `1192`（万位消失）——**不是不认识五位数**
（四位数以内数位分解/对齐/进位全对），是**复制电路宽度绑定**：
注意力头学的是"取回 4 个数字 token"，5 个时最高位被丢。

**关键对照**：序公理外推 100% vs 读位 0%——序判断不需要逐位复制
（一次注意力扫描），数位分解需要完整复制（逐 token 机械操作，宽度绑定）。

### 用户之问："一般大模型如何解决？数应当被理解成一个整体"

我方调研四个机制：
1. Tokenizer 策略（Llama3 逐位切分 vs GPT-4 不一致切分）
2. 数据广度（见过 1~20+ 位所有宽度）
3. **数字嵌入（PaLM PN / xVal）**——正是"数作为整体"的技术实现：
   嵌入空间里 `11962` 与 `11963` 相邻（值相邻），而非字符串无关
4. CoT 写中间步骤

诚实限制：数字嵌入解决**输入侧**（读/复制），但自回归**输出侧永远逐 token**——
完整解法需三层叠加（嵌入 + 算法化 CoT + 数据广度锚点）。

### NAVE 方案（我方设计，DESIGN_nave_v2.md，未实施）

数字值嵌入：每个数字位置注入**当前前缀值**（因果安全：读到第 1 位 `1` 时
不可能知道完整值，只注入 `[1, 11, 119, 1196, 11962]` 的前缀），
值编码用数位×位权可加编码（与 CoT 分解同构，宽度可外推）。
C0~C3 对照实验设计。**用户未批准实施，提出更好的想法（见下）。**

### 用户的"大纲渐进展开"思想（2026-09-16，v2 核心设计）

> "拆解意义的时候应该是个类似大纲的结构，每个小结构还能细分，比如一个整体数字，
> 可以用一个 x 代替，他们结构一样的，具体计算的时候又需要理解每个位数。渐进展开。"

我方形式化为三层：

```
【绑定层】  设 x = 11962, y = 1685        ← 数字变成符号，推理只谈 x/y
【公理层】  按位对齐，从个位起相加，满十进一  ← 纯符号规则，宽度无关
【展开层】  逐位下钻，每步只碰一个位      ← N 个宽度 1 的操作
```

**v1 数据为此提供了直接证据**：

| 测试 | 结果 | 推理对象 |
|---|---|---|
| 序公理五位数外推 | 100% | 纯符号 |
| 挖洞后继 | 100% | 纯符号 |
| 五位数后继/加法 | 0% | 字面量搬运 |

**凡推理在符号上进行，宽度无关；凡推理需要搬运字面量，宽度绑定。**
大纲方案 = 把第二类转化成第一类。

核心转变：**把"一个宽度 N 的操作"换成"N 个宽度 1 的操作"**。
单步复杂度常数化，宽度只决定行数，不改变任何行的结构（"他们结构一样的"）。

层级细分（`11962 = 119×100 + 62`，深度 O(log N)）留 v3——v2 先用线性逐位
（每步最简，8 层模型最容易学）。

### v2 数据格式（当前设计，待三探针诊断确认）

```
问: 11962 + 1685 = ?
读位 x: 1,1,9,6,2（5位数）
读位 y: 1,6,8,5（4位数）
公理: 按位对齐，从个位起相加，满十进一
个位: x=2, y=5, 2+5+0 = 7, 写7进0
十位: x=6, y=8, 6+8+0 = 14, 写4进1
百位: x=9, y=6, 9+6+1 = 16, 写6进1
千位: x=1, y=1, 1+1+1 = 3, 写3进0
万位: x=1, y=0, 1+0+0 = 1, 写1进0
合成: 1,3,6,4,7
答: 13647
```

要点：推理链中**没有任何宽度 >1 的字面量发射**；`y=0` 显式化对齐；
`答` 是紧邻合成行的本地读出；**训练只用 1~4 位，5/6/7 位留外推测试**。

## 五、v2 → v3 的讨论与实施（2026-09-17 ~ 09-18）

### v2 结果回顾（大纲格式的墙"转移"）

v2（绑定行分段 `x := 9,7,4,4,3` + 竖式行）实测：
- ✅ 3/4 位后继/加法 **100%**、序 100%、挖洞 80%——大纲格式的**执行**正确
- ❌ 5 位仍 0%：失败样例显示 `理解: 算式 F, F=s(x), x := 9,7,4,4`——**绑定行丢位**
- 结论：v2 的墙在**绑定行**（唯一还整体抄写的地方）

### 用户新增设计：循环 + 计数格式

> 用户："对于加法的竖式拆解，用循环+计数的方式表达能短不少。"

形式化为（**声明 + 逐次展开**，绝不用幂记号压缩）：
```
问: 4483+579 = ?
理解: 算式 F, F := a+b, a := 4,4,8,3, b := 5,7,9
算法: i 从 1 到 4 循环：s_i := a_i+b_i+c; d_i := s_i mod 10; c := s_i div 10（c 初值 0，a_i 从右往左取）
i=1: a_1=3, b_1=9, c=0, s_1=3+9+0=12, d_1=2, c:=1
...
结束: c=0，无补位
合成: 5,0,6,2
答: 5062
```

**收益（用户洞察）**：索引 `i` 无上限（位名有尽头）+ 每行**完全同构**（i=1 与 i=8 只差数字）。
**代价（诚实标注）**：token 数**不省**（每行多了 `i=`/`c=`/`s_1=`/`d_1=`/`c:=` 显式状态标注，这是对抗 4 层深度限制的必要代价）。

**推演验证**：`check_chain_v3_tmp.py` 14 用例（含补位溢出 `9999+1`、连续进位、不等长、8/9 位），
生成器与校验器**两套独立实现**交叉核对，0 错误。

### 其他定案

| 议题 | 结论 |
|---|---|
| 序关系表达 | **方案 A**：`命题 P := (a<b)`（范畴正确：项绑项 `F := a+b`，命题绑命题）+ 传递闭包 + 答 `⊤/⊥` |
| 为何不用幂记号 `s²` | 会把 N 步压成 1 次操作 = v1 失败模式；必须逐步展开 |
| 英文读法 | **英式**：`and` 作分段边界信号（与中文"零"对称） |
| 读法层范围 | N1~N5 全做（中文/英文/缩写/万级） |
| 序差值范围 | **≤10**（用户"先学走再学跑"：公理 O(差值) 是本义，训练不用大数；评估测 20~60 看递归） |
| LaTeX | 后置（v1 用 Unicode 已足够） |

### OOM 排查（重要工程收获）

连续 3 次 OOM（batch 32/24/16）→ **实测数据定位根因**（详见 `V3_SUMMARY.md` 第五节）：
- 先怀疑 8/9 位锚点 → 实测否定（仅 4 条，非主因）
- 真因：HF 把 logits 升 fp32，`16×305×151646×4 = 2.96GB`（v3 序列比 v2 长 1.62 倍）
- 精度实测：bf16 算 loss 梯度误差 **1.35%**；fp16 需 scaling
- **解法：分块 fp32 loss**（数学等价，对拍 `相对差 0.0000%`）+ 附带提速（1.55h vs 预估 7h）

### v3 实测结果与根因

**达标**：3/4 位后继/加法 100%、挖洞后继 100%、序 ⊤ 100%、序递归泛化 100%、序宽度外推 100%、
读法 4 位中文 100%、缩写→数值 100%

**未达标**（核心发现）：
```
问: s(97443) = ?（5 位）
→ 理解: 算式 F, F := s(x), x := 9,7,4,4     ← 只有 4 个数字
→ 算法: ...i 从 1 到 4 循环                  ← 上界 4（应 5）
```
**墙从"复制丢位"转移为"位数不可知"**：循环格式解决了"每步宽度 1"，
但循环上界 `k` 需要知道**位数**——而"位数"从未被显式训练（是数据的隐含属性）。

**序关系方向语义丢失**：`5503<5497` 应 ⊥，模型自动从 min(5497) 数到 max(5503) 答 ⊤。
根因：训练数据生成器内部 `lo,hi=min,max` 统一从小的数起数，模型**从未见过"从 a 出发不可达"**。

**两个次要 bug**：英文读法 prompt 与中文完全相同（脚本）；3 位加法仅 99 条（数据配比）。

### v4 待解决（用户思考中）

1. **位数不可知**（核心）→ 新增显式"数位数"训练目标（且数位数自身也需宽度无关）
2. 序方向语义 → 训练数据加"从 a 出发，只会越来越大"的完整链
3. 组合泛化 0%（`s(s(1400))` 丢位）→ 位数问题解决后应改善
4. 英文 prompt / 3 位样本配比（工程）

## 七、议题：训练数据顺序是否有影响（2026-09-18 用户提问）

### 分析（三个层次，影响幅度差别巨大）

**层次 1：样本"内"的顺序 —— 硬约束（已实测）**
CoT token 先后决定成败：`理解→算法→逐位→合成→答案`。
答案若在步骤之前，模型学到"答案与步骤无关"→ 退化为查表（v2 组装解耦 8/16 失败即此因）。
**顺序错 = 能力消失。**

**层次 2：样本"间"的顺序 —— 有影响，幅度中等（未实测）**
- 随机洗牌：SGD 期望正确、避免 batch 内偏差（v1/v2/v3 现状）
- 课程（易→难）：小模型早期用简单样本建立可复用特征，可能加速收敛
- 严格分阶段：灾难性遗忘风险（旧系列 v8.2→v8.3 见过新知识冲淡旧能力）
- **诚实声明**：v1/v2/v3 均纯随机，**无"顺序"对照数据**，以上为推测

**层次 3：数据"配比" —— 比顺序重要得多（v3 血的教训）**
加法 3 位 99 条 vs 4 位 4305 条（43 倍差）→ 3 位 26.7% vs 4 位 100%。
**配比失衡，顺序怎么调都救不了。**

### 机制：最后一轮偏置（recency effect）
模型对最后见到的数据更敏感。最后一轮偏向某类 → 最终状态偏向该类。
→ **推论：每轮（尤其最后一轮）全量随机洗牌是保证能力均衡的最简手段**；
分阶段训练反而可能让最后一轮只含某一类。

### 建议
| 措施 | 优先级 |
|---|---|
| ① 修配比（各宽度样本量拉齐） | **最高** |
| ② 保持全量随机洗牌（避免最后一轮偏置） | 高 |
| ③ 轻度前置（前 20% 步喂短样本/定义/公理，之后全量随机） | 中（可选） |
| ④ 硬分阶段 | **不建议** |

注：`[D] 定义层 ×40`/`[A] 公理层 ×30` 的高重复已是隐含"频率课程"，方向正确。

### 可做对照（v4 反正要重训，+0 成本）
| 组 | 方式 |
|---|---|
| V4-A | 全量随机（基准） |
| V4-B | 前 20% 步只喂短样本（≤2 位 + 定义/公理），之后全量随机 |

比较 5 位外推 / 3 位加法 / 读法差异。若 B 显著优 → "顺序有影响"成为结论。

## 八、议题：课程学习（依赖课程）——用户提出"先训数位数，再训加法"（2026-09-18）

用户："我个人感觉可能训练顺序能加快学习速度，比如我们先训练数位数，
再训练多位数加法，可能他就能理解位数的概念了。人类也是先学加法再学乘法，
从基础到深度思考、从易到难通常最有效。不知道大模型是否也这样。"

### 研究图景（诚实）
| 立场 | 证据 |
|---|---|
| 支持 | Bengio et al. 2009（原始课程学习论文）：易→难加速收敛。CV/NLP 多任务有正面结果 |
| 反对 | 大模型预训练普遍**不用**课程（GPT/Llama 随机洗牌）；数据规模淹没课程效应 |
| 关键区分 | **"难度课程"收益不稳定；"依赖课程"（前置技能先学）收益稳定** |

### 用户提的是"依赖课程"（不是难度课程）——这个区别是关键
```
难度课程（不稳定）：先 1 位加法 → 再 4 位加法     只是"简单/复杂"
依赖课程（有效）：  先"数位数" → 再"用它做加法"   后者依赖前者的产出
```
加法循环的 `i 从 1 到 k` 里的 **k 正是数位数的输出**——真实依赖关系。
v3 失败正是因为模型被迫**同时**学两件事（"k 是多少" + "如何用 k"），两者都没学好。

### 为什么大模型预训练看起来不用课程（三条件全不适用我们）
1. 语料无显式依赖链（网页文本间无"必须先学 A"）
2. 数据规模淹没课程效应（1T token 下顺序被平均掉）
3. 目标不同（预训练要广泛能力，我们要精确掌握规则链）

我们的场景三条件全反：**数据小（5 万条）+ 强依赖链 + 目标精确** → 课程最该发挥作用处。

### 用户类比需修正（诚实提醒）
"先学加法再学乘法"——**乘法不是"更难的加法"，是新运算结构**（分配律）。
人类学乘法的前提是"加法已自动化"，不是"加法位数更多"。
同理：若 v5 引入减法借位/乘法错位，那是**新结构**，依赖的是"基础机制已自动化"。

### 设计：渐进加权（而非硬分阶段）
| 训练进度 | 数位数层 | 加法/后继 | 效果 |
|---|---|---|---|
| 前 30% 步 | **50%** | 30% | 依赖层先行建立，成为可复用技能 |
| 中 40% 步 | 30% | 45% | 过渡（加法开始"用"位数） |
| 后 30% 步 | 20%（自然） | 55% | 收敛到目标分布 |

**全程含所有任务（不硬切换）** → 避免灾难性遗忘 + 避免"最后一轮偏置"；
但早期给依赖层更高权重 → 让 k 先学会。

### 对照实验（v4 反正要重训，成本 +0）
| 组 | 方式 | 目的 |
|---|---|---|
| V4-A | 全量随机（基准） | 现状 |
| V4-B | 渐进加权 | 验证依赖课程 |
| V4-C（可选） | 硬分阶段（先只训数位数 2 epoch） | 验证是否真遗忘 |

判据：5 位外推 / 3 位加法 / 读法成绩 + **达同等 eval_loss 所需步数**（验证"加速"）。
- B 用更少步达到更高准确率 → 用户直觉证实，方法可复用
- B≈A → 该规模对顺序不敏感（有价值的负结论）
- C 明显差 → 证实硬分会遗忘，反证"渐进加权"必要性
