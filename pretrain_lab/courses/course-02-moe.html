MoE：稀疏计算如何扩大模型容量

先把“专家”放回正确的位置：经典 Transformer MoE 通常在网络内部用小 router 为每个 token 挑选若干 FFN 专家；它不等同于一个模型调用外部程序，也不保证专家天然拥有“数学/代码”等人类命名的技能。

1. Dense 与 MoE 的结构差别

Dense 层中，每个 token 都经过同一组 MLP 参数。MoE 层把该 MLP 换成 N 个专家 MLP，router 根据当前 token 的隐藏状态给专家打分，选 Top-k，再把所选输出按 gate 权重合并。Transformer 的 attention 通常仍由所有 token 共享。

标准做法是 token 级、逐 MoE 层做选择；不同 token 可以走不同专家，同一个 token 在不同层也可能有不同分派。Switch Transformer 的简化路由选择 Top-1；Mixtral 8×7B 每层 8 个 FFN 专家，每个 token 选 2 个。

原始论文：Switch Transformers、Mixtral of Experts。

2. Router、Top-k 与训练难点

router 可用一个线性层把隐藏状态 h 投影成 N 个 logits，再 softmax 得到各专家分数。Top-k 选中专家后，通常会对入选 gate 权重重新归一化：

s = softmax(Wᵣh)；S = TopK(s)；y = Σᵢ∈S (sᵢ / Σⱼ∈S sⱼ) · Eᵢ(h)

如果 router 总把 token 发给少数专家，会造成专家利用失衡；实际 MoE 还需处理 capacity、丢弃/溢出 token、跨 GPU all-to-all 通信、负载平衡辅助损失和训练稳定性。稀疏只减少每 token 激活计算，不自动减少所有专家权重的存储量。MoE 的总参数、活动参数、显存和吞吐是不同指标。

Dense 模型稀疏 MoE
每个 token 执行同一套权重；部署权重较直接。每个 token 执行少数专家；总容量可大于每次活动计算。
计算和参数量随模型宽度共同增加。Router 分派、专家负载和设备通信带来额外系统成本。
核心对照量：参数、token/s、显存、质量。还要报 total params、active params/token、专家使用率、丢 token 比例。

Mixtral 论文报告约 47B 总参数、每 token 约 13B 活动参数；这说明稀疏激活的“每次算多少”和“总共存多少”要分别看。不能把“13B 活动参数”说成“显存只需放 13B 参数”。

3. 示例 1 · 实际跑一次 Top-2 加权路由

这个小程序用人为给定的 router 分数和专家输出，把 Top-2 与加权求和跑出来。它演示的是机制，不是训练好的语言专家。

import torch
x = torch.tensor([1.0, 2.0])
scores = torch.tensor([2.0, 1.0, 0.0])
chosen = torch.topk(scores, k=2)
gate = torch.softmax(chosen.values, dim=0)
outputs = torch.tensor([[1.,0.], [0.,3.], [100.,100.]])
y = (gate[:,None] * outputs[chosen.indices]).sum(dim=0)
print(chosen.indices.tolist(), gate.tolist(), y.tolist())

本机实跑：专家索引 [0,1]；权重约 [0.731059,0.268941]；合并输出约 [0.731059,0.806824]。专家 2 的大输出不参与，因为它没有进 Top-2。

4. 示例 2 · 数字复制宽度：表示、复制与计算拆开看

在此前整段生成实验里，任务的第一步往往先把 1234567 原样复制到新的绑定/计算行。若模型只在较短数字上见过整段复制，长串可能漏位；复制错后，即使个位规则本身正确，最终答案也会错。历史 v4-A 的复制 probe 五位为 0%；NAVE v5-C1 把数字前缀值注入输入表示后，四位复制约 60%、五位约 20%，仍未越过设定的宽度判据。NAVE 改善的是数值表示信号，输出侧仍需逐 token 生成并对齐；它没有自动解决任意宽度复制。

你的后续设计改变了控制方式：不要每轮让模型重写整串操作数；控制器持有原始数字和游标，每次只抽取最右位 (a_digit,b_digit,carry)，调用同一个小专家，消费一位并更新 carry，直到输入耗尽。这里模型做固定宽度局部映射，循环控制负责位宽。

1234567 + 7654321 = 8888888。单列 MLP 只有 8,260 个参数，训练覆盖完整 200 个状态并穷举 200/200 正确；循环扩展到 100 位全 9 + 1 仍正确。准确表述是：在这个加法原型中，通过结构化迭代消除了模型一次复制整串所需的宽度增长。这不是证明 Transformer 无法复制，也不是证明所有数学都只需固定局部网络。

此前整段 trace 专家使用 1–4 位训练，却在 5–8 位测试失败；这个负例显示改变文本模板不等于解决数字宽度问题。保留它，是为了讲清楚从失败定位到循环设计的实验路线。

5. MoE 和你的外部专家系统：相关但不是同一结构

你的路由器在请求层选择“整数计算器 / 逐位数学专家 / UNKNOWN”，再从 package 表按需取 payload。标准 MoE 则常在 Transformer 的每层内部按 token hidden state 分派 FFN 专家，专家参与网络前向与反向训练。二者都“有路由和多个计算分支”，但路由单位、专家位置、训练目标、payload 生命周期都不同。课程第 3 课会把这两个层次画开讲。

不要只因有“router + expert”就把一个系统称为标准 MoE。准确说法是“模块化专家路由原型”，然后逐项比较它与 token-level sparse MoE。
