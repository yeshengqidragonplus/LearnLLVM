1. 本课先看全貌：Dense Decoder-only 模型

“稠密”表示每次前向传播时，输入 token 都会经过模型中每一层的主要参数。GPT 类模型通常使用 Decoder-only Transformer：token embedding 与位置机制提供初始表示，重复若干 Transformer block，最后把隐藏状态投影到词表上，得到下一 token 的分数。

Transformer 原论文提出的是 Encoder–Decoder 序列转换结构；GPT 采用 Decoder-only、自回归生成路线。训练时可以并行计算一条序列各位置的预测，生成时必须拿到上一个 token 才能继续。来源：Transformer 原论文、早期 GPT 论文。

2. 示例一：I love you 如何变成向量并预测

本项目 tokenizer 的实测切分是 [I, Ġlove, Ġyou]，ID 为 [40, 2948, 498]。可见符号 Ġ 表示 token 前有空格。ID 是查表索引，不是词义；embedding 矩阵第 40、2948、498 行分别提供三个可训练向量。若教学模型 d_model=64，输入形状为 [batch=1, time=3, width=64]。RoPE 在注意力计算中注入位置关系。

为什么需要 Q、K、V？从“如何找对信息”推出来

假设句子里的每个 token 都有一个向量。处理 “you” 时，模型需要从前文挑出对当前预测有用的信息。最直接的办法是：把“当前想找什么”与“每个历史位置有什么特征”比较，得到权重，然后把相关位置的信息汇总起来。但用于“找”的特征与真正要“取走”的内容不必相同，因此注意力把它们分成三种可学习的表示：

名称直观问题在计算中的角色
Query（Q）当前位置正在寻找什么信息？发起查询的一方
Key（K）历史每个位置有哪些可匹配线索？与 Query 比较，算匹配分数
Value（V）如果这个位置相关，要把什么内容传过去？被注意力权重汇总的信息

同一个隐藏向量 X 通过三组不同的可训练矩阵投影：

Q = XWQ　　K = XWK　　V = XWV
score(i,j) = Qᵢ · Kⱼ / √dₖ
weight(i,j) = softmaxⱼ(score(i,j) + causal mask)
outputᵢ = Σⱼ weight(i,j) × Vⱼ

除以 √dₖ 用来控制点积数值尺度，使 softmax 不至于过早变得极端。因果遮罩把未来位置设成不可见。最终再经过输出投影、残差和归一化，送到后续子层。

为什么不直接用一个向量相似度？如果 Q、K、V 完全共用同一表示，模型就不能分别学习“用什么条件找”“什么特征可匹配”“匹配后传什么内容”。分开投影让匹配规则和被传递的信息都可学习。它是一种灵活的信息检索/混合机制，不表示模型内部真的存着人类定义的三种字段。

多头：同一段输入用几套检索视角

若 d_model=64 且有 4 个头，每头宽 d_head=16。Q/K/V 从 [1,3,64] reshape 成 [1,4,3,16]；每个头计算自己的 [1,3,3] 位置分数，再把四头输出拼回 64 维并通过输出矩阵。不同头让模型可以在不同子空间同时计算多组关联，再把结果合并；单头可能需要在同一组通道里兼顾多种关系，多头提供了并行表示能力。但头不保证各自形成“主语头”“定语头”，也不是越多越好；每头维度变得太窄时，表达能力可能受限。

Logits 是什么？

最后，LM Head 把每个位置的隐藏向量投影到词表的每个 token，产生一串尚未归一化的原始分数，这就是 logits。logits 不是概率；对它做 softmax 才得到总和为 1 的概率分布。语言模型在每个位置都有一个词表分布。

logits shape = [B, T, V]
本例：B=1 条句子，T=3 个位置，V=151,646 个 token
所以 logits = [1, 3, 151646]

这表示 3 个位置各有 151,646 个候选 token 分数。训练时用每个位置真实的“下一个 token”作为目标算交叉熵；推理时主要取最后一个位置的 logits 来选择续写 token。

可运行 Demo · 检查 tokenizer 与 logits

from transformers import AutoTokenizer, Qwen2Config, Qwen2ForCausalLM
import torch, sys
sys.stdout.reconfigure(encoding="utf-8")

tok = AutoTokenizer.from_pretrained("tokenizer")
ids = tok.encode("I love you", add_special_tokens=False)
print(tok.convert_ids_to_tokens(ids), ids)
V = max(len(tok), tok.eos_token_id + 1, tok.pad_token_id + 1)
cfg = Qwen2Config(vocab_size=V, hidden_size=64, num_hidden_layers=1,
    num_attention_heads=4, num_key_value_heads=4, intermediate_size=170,
    max_position_embeddings=512, tie_word_embeddings=True)
model = Qwen2ForCausalLM(cfg)  # 随机初始化：只查看结构
x = torch.tensor([ids])
with torch.no_grad():
    out = model(input_ids=x)
print(x.shape, out.logits.shape)

本机实测：token IDs [40, 2948, 498]；logits 形状 [1, 3, 151646]。随机初始化模型不会正确理解或续写；Demo 只用于辨认张量和分数。

3. 示例二：复杂句子如何携带角色和关系

句子：“你们去绕后包围那只正在喝水的大象。”为了讲解，先按语言成分标注（不是声称 tokenizer 一格就对应一个词）：

执行者 / 主语你们
方式 / 状语去绕后
动作 / 谓语包围
目标 / 宾语大象

“那只正在喝水的”是定语，用来限定目标是哪一只大象。一个能执行任务的听者需要把这些分散的信息组合起来，而不是只记住连续出现过的短语。

把相同输入分别交给三种序列模型

模型一步步看到什么可能捕捉到什么这句里暴露的限制
CNN：卷积窗口滑过“去｜绕后｜包围”“那只｜正在｜喝水”“喝水｜的｜大象”等局部组合“绕后包围”像方式加动作；“正在喝水的”可能修饰后面的“大象”单个窄窗口难同时包含句首“你们”和远处动作/目标；多层扩大感受野，但信息需逐层传递
RNN：依次读“你们”→“去”→“绕后”→“包围”→修饰语→“大象”，每一步更新隐藏状态状态可携带当前执行者、动作和未完成目标的线索；输入天然支持流式处理后续只能使用压进状态的信息；句子增长时远处细节可能丢失/混淆，训练步骤也有串行依赖
Transformer：每层为各位置计算 Q/K/V；后面的 token 可对允许范围内的前文位置分配注意力，再更新表示处理句末“大象”或句末标点时，可以直接从“你们”“绕后”“包围”和“正在喝水的”读取线索，并在多层中组合attention 提供直接连接能力，不保证权重一定符合语法分析；错误仍要靠数据与任务评测发现

逐步跟踪它们怎样处理同一句话

CNN：窗口提取局部模式
  1. 窗口扫到“绕后｜包围”，形成方式与动作的局部特征候选。
  2. 窗口扫到“正在喝水的｜大象”，形成修饰语接名词的局部特征候选。
  3. 较深卷积层把邻近特征继续组合，尝试连接“你们”与动作、目标。
  4. 要建立句首执行者与句尾大象的关系，信息需跨多个卷积层传播；窗口/层数不足时路径可能太长。
RNN：状态逐步携带还没完成的结构
  1. 读“你们”：状态开始积累执行者线索。
  2. 读“去绕后”：状态追加执行方式。
  3. 读“包围”：状态有了核心动作，但还等待对象。
  4. 读“那只正在喝水的”：状态要暂存一段目标限定。
  5. 读“大象”：将目标名词和前面的限定组合，得到完整动作关系候选。

这些是教学上描述模型需要利用的线索，不代表隐藏状态中真的有“执行者”字段。

Transformer：以句末位置为例，逐层从前文取信息
  1. 每个词先转换为 embedding，并带上位置线索。
  2. 每层由隐藏向量生成 Q/K/V；对句末“大象”或句末标点位置，Query 可与前面各 Key 计算相关性。
  3. 因果 mask 允许句末位置看见整段左侧前文，但不允许早期位置偷看后文。
  4. 多头在不同可学习子空间分别混合 Value；拼接输出后，残差和 MLP 更新表示。
  5. 后续 block 在已更新表示上继续组合，再由 LM Head 给下一 token 产生 logits。

这里的 Transformer 箭头只画因果允许的信息方向：句末位置可以查看左侧所有 token，早期位置不能偷看右侧未来。训练好的模型是否把它们组合成正确任务意义，仍要用新人物、新动作、新目标、新修饰语测试。Transformer 的优势是远处信息可直接参与当前表示，且同一层训练能并行计算位置；它不是自动生成一棵完美语法树。

同一句换成“你们去绕后包围那只正在休息的犀牛”，结构大体相同但词语组合改变。能处理这种没见过的组合，才是我们要评估的组合泛化；CNN、RNN 和 Transformer 都需实验验证，并非架构名称本身保证成功。

4. 为什么要堆多层？一层一层组合信息

把 Transformer 想成反复加工同一张 token 表示表。输入层只给出 token 向量和位置线索；一个 block 做一次“依据上下文更新表示”，再做一次逐位置 MLP 特征变换。下一层拿到的已经是更新过的表示，可以继续建立更复杂的组合。

输入各 token 的向量 + 位置
较浅层融合邻近词、常见局部关系
中间层把角色、动作、修饰线索组合
较深层/输出为当前预测形成上下文状态

以前例来说，一些浅层头可能学会“正在喝水的”与“大象”的局部联系；更深的计算可以在更新后的表示上组合“目标是哪只”“谁来包围”“绕后是什么方式”。这只是便于理解的层次描述，真实网络不保证某层对应一个明确语法步骤。

X ← X + MHA(Norm(X))　（按上下文混合）
X ← X + MLP(Norm(X))　（逐位置变换特征）
重复 L 次 → final norm → LM Head

为什么一层不够？一层只做有限次投影、关系混合和非线性变换。深层模型能把前面已混合的特征再作为新输入，反复组合，形成更复杂的函数。但“多层”本身不等于更聪明：如果数据、训练步数、优化或上下文不匹配，多出来的层可能只增加计算而学不到有效结构。

层数 L 怎么选？

没有脱离任务与预算的通用最佳层数。先确定目标任务与可用显存/时间；选一组固定总训练 token、数据、优化器和近似计算预算的配置，用不同 L/d 做对照；比较 validation loss、目标任务、外推/OOD、tokens/s 和峰值显存。保持其余因素可比，并多跑种子或报告波动，再决定是否增加深度。

层数增加的收益潜力层数增加带来的成本/风险训练时常用应对
更多轮表示变换；上下文信息可经过更多次组合；在固定宽度下扩大函数表达能力参数量和每个 token 的计算大致随 L 线性增；前向/反向的层间依赖更深；激活保存更多；单卡显存或训练时长可能上升；小数据时更易记忆训练集残差与 pre-norm 稳定深层优化；activation checkpointing 省显存但增加重算；用验证集选 checkpoint；必要时降 batch/长度、调学习率或增加多样数据

5. 上下文窗口大小由什么决定？

上下文长度 C 以 token 数计，prompt、聊天历史、工具回传和预留生成空间都占用窗口。模型参数量本身不能推出 context 长度。实际可用范围由位置机制/模型配置、训练时见过的长度、推理引擎限制，以及显存和时延预算共同决定。

因素决定什么怎么检查
架构配置与位置机制position embedding 表、RoPE 基础配置/扩展、模型声明的最大长度查看 config、位置模块和模型卡
训练长度和数据长距离信息是否见过、长上下文能力是否训练出来在不同长度和不同位置设计检索/依赖评测
推理软件max sequence、KV allocator、生成上限、批处理设置检查 serving runtime 参数和截断行为
显存与速度权重、KV cache、临时 attention 张量、并发与首 token 延迟测峰值显存、吞吐、时延随长度变化
KV cache bytes ≈ 2 × L × B × T × n_kv × d_head × bytes/element

例：24 层、batch=1、8 个 KV heads、head_dim=128、BF16 时，8K token 的 KV cache 约 0.75 GiB，256K 约 24 GiB；还没加模型权重与临时张量。全注意力 prefill 的位置对规模近似 T²：长度加倍，未优化的注意力计算/分数规模约变为 4 倍。FlashAttention 可降低中间存储和搬运，但 context 并非免费。

本项目训练器的 MAX_SEQ_LEN=512 是这条教学训练管线的设置，不是 Transformer 或所有 Qwen 模型的固定上限。窗口也需扣除输出预算：可输入 prompt ≈ C − 历史/系统/工具 token − 预留输出 token。

6. 根据目标估算模型大小：结构参数逐项看

模型配置不是一组神奇默认值。每项参数都改变表示容量、计算路径、显存或可接收序列；应由任务、数据、训练预算和推理约束共同决定，再用对照实验验证。

intermediate_size mMLP 内部扩展宽度，SwiGLU 常用三组矩阵需要多少逐位置非线性变换容量？MLP 参数近似 3dm；m 过大增加参数和计算
max_position / max_seq_len配置或训练管线允许的最大序列长度样本真实长度、目标依赖距离、显存和时延预算是多少？attention prefill 位置对成本近似 T²；KV cache 随 T 线性增
batch_size / grad_accum每次权重更新累计看多少 tokenGPU 装得下多大 micro-batch？目标 tokens/update 是多少？batch 增大通常增显存；梯度累积以更多步数换较小单步显存
learning_rate / schedule每次优化器更新权重的步幅及其随训练变化pilot loss 是否稳定下降？warmup/衰减时点是否匹配步数？过高可发散，过低学得慢；模型规模和总步数影响合适范围
hidden_act / normMLP 非线性与每层归一化是否沿用已验证架构？训练深度和数值稳定性如何？改变 block 函数形式和优化行为；需与权重/实现匹配
tie_word_embeddings输入 embedding 与输出 LM Head 是否共享权重模型设计是否绑定？参数预算和训练效果怎样？共享可省约 V·d 参数；不一定适合所有模型
dropout / weight_decay训练期随机失活与权重正则化数据量、重复度和 train-valid gap 如何？可能缓解过拟合，也可能妨碍充分拟合；不是默认越大越好
warmup / scheduler / grad_clip学习率启动/衰减与梯度幅度约束训练步数、batch 与 loss 稳定性如何？需按总步数和 pilot 设计；过短训练不适合照搬长程配方
dtype / optimizer数值精度、权重/梯度/状态存储与更新方式GPU 支持哪种精度？数值稳定性如何？BF16/FP16 可省显存/提速但需验证；Adam 状态有额外内存

参数量如何粗算

对输入输出 embedding 绑定、MHA + SwiGLU 的 decoder，忽略 norm/bias 小项：

P ≈ V·d + L·(4d² + 3d·m)
若输出 embedding 不共享，再加 V·d

Q/K/V/O 四个投影约 4d²；SwiGLU 的 gate/up/down 三组矩阵约 3dm。注意力头数 h 在固定 d 的普通 MHA 中主要切分投影维度，并不会将这四个矩阵再乘 h。真实模型可能有 GQA、bias、不同 MLP ratio 或权重绑定，最后用代码统计。

教学模型配置实测参数这组实验说明什么
V=151,646，d=64，L=1，h=4，m=1709,754,752词表 embedding 约 9.71M，极小模型里词表能占大头
d=64，L=1，h=89,754,752固定宽度只改变头划分，参数数不变
d=128，L=1，h=419,607,936加宽让 embedding 和每层矩阵一起变大
d=64，L=4，h=49,902,784加深逐层加 block；本例增量较小因 embedding 占主导

怎样按目标选一个起点

  1. 写成功判据：目标行为、输入长度、延迟/显存限制、可用训练 token。
  2. 先做能检验机制的小模型：例如本地 9.75M 随机初始化配置只验证张量和训练代码，不是语言能力目标。
  3. 固定数据/token 数与计算预算，对照“更深 L”与“更宽 d”，测验证 loss、任务指标、外推、峰值显存和 tokens/sec。
  4. 扩大前先判断数据量够不够。模型更大但训练 token/步数不足，会浪费容量；Chinchilla 研究提醒模型参数与训练 token 要在给定算力下共同规划，但它的比例是实验结论，不是通用硬性配方。

7. 预训练数据怎样准备

定义数据边界来源、许可、隐私、任务范围
清洗与去重乱码、模板、重复、低质内容
划分集合按文档/来源切 train、valid、test
tokenize 与打包统一 tokenizer、EOS、长度与 mask

准备工作要保留可复现的语料清单、版本、过滤规则和数据哈希。先去重，再划分集合，避免相同文档或高度近似内容跨集合泄漏。验证集和测试集要与训练样本隔离；测试集只用于最终比较，不能反复调参。

普通 next-token 样本把文档 tokenize，按约定追加 EOS；将 token stream 切成长度不超过 context 的片段。是否跨文档 packing、是否屏蔽文档边界 loss，应明确写入协议。保存 token 数、长度分布、过滤前后数量和抽样审查结果；“文本行数”不能代替训练 token 数。

本实验室现有数学数据有版本差异：当前生成器输出 59,078 条，与旧记录的 94,942 条不同，不应宣称精确复现。命令和数据约定见 README。

8. 训练 GPU 内存与训练时长怎么估

显存要分项记账

占用项主要取决于降低方式
模型参数、梯度、Adam 状态参数 P、精度、优化器、是否有 FP32 master weights小模型、低精度、8-bit optimizer、分片/卸载
激活值层数、batch、序列长度、hidden/MLP 宽度降低 micro-batch/序列长、activation checkpointing、FlashAttention
Attention 中间状态batch、heads、T² 位置矩阵及实现FlashAttention、缩短 T、分块 loss
临时缓冲与碎片CUDA kernel、workspace、allocator、后台显存占用留安全余量、测真实峰值、避免同卡并发

非常粗略地说，AdamW 混合精度训练的参数/梯度/优化器状态可能合计约 12–18 bytes/parameter；实现细节会改变这个值，而且这不包括激活、临时张量和缓存。1B 参数仅状态就可能需要十几 GB，训练显存通常比推理权重多得多。笔记本应先用 nvidia-smi 看本机可用显存，再做逐步递增的短 pilot；4060/4070 Laptop 显存配置也以具体机器为准。

训练时长用实测吞吐估

时间（秒）≈ 训练总 token 数 ÷ 实测训练 tokens/秒 × epoch 数
粗略计算量起点：dense Transformer 训练 FLOPs ≈ 6 × P × D

D 是处理的 token 总数。FLOPs 公式忽略部分 attention、数据读取、评估、保存和通信开销；序列长度、batch、精度、GPU 功耗/散热都会改变真实吞吐。最靠谱的预算方式是用目标模型和序列长度跑几十到几百步，记录稳定 tokens/sec、峰值显存，再外推总步数，并为验证与 checkpoint 留时间。

例如 1M tokens、稳定吞吐 1,000 tokens/s，一轮纯训练计算约 1,000 秒（16 分 40 秒）；实际墙钟时间还要加评估、保存和可能的停顿。跨两台电脑比较时保持模型、数据、序列长度、batch、精度和步数一致。

9. 示例三：一次训练如何组织输入、标签与 loss

假设样本 token 是 [I, love, you, EOS]。自回归训练会错开输入与目标：

input: I love you
target: love you EOS

Decoder 对输入位置并行前向，每个位置只允许看当前及左侧；logits 形状为 [batch, time, vocab]。交叉熵对每个有效位置的真实目标计算负对数概率，再对目标 token 平均。忽略 padding 的位置需用 mask 排除。

本实验室的 smoke_test.py 会创建小模型、执行短训练、对拍 loss、保存重载并做短解码。它是链路自检，不是有用语言能力证明。正式实验必须有独立验证集和任务评估，不能把 train loss 降了当作模型学会泛化。

10. 如何评估训练结果

评估要同时回答“优化是否工作”“数据是否学对”“目标能力是否能泛化”。

层次指标/测试能说明什么
训练过程train loss、valid loss、学习率、梯度范数、tokens/s、峰值显存优化是否下降、是否稳定、资源是否符合预期
语言建模留出集 NLL / cross-entropy；同 tokenizer 同切分下的 perplexity模型对未参与训练的同分布 token 序列预测是否改善
目标任务准确率、exact match、结构/步骤检查、固定提示集目标行为是否达标
泛化与鲁棒新措辞、新长度、新组合、边界长度、失败样例是否记模板、是否只在训练范围内工作

比较实验时固定 tokenizer、数据划分、prompt、解码策略和指标定义；保留分母、代码版本与模型权重哈希。loss 和 perplexity 只能说明概率预测质量，不能单独证明事实可靠、推理正确或复制宽度已泛化。

11. 欠拟合与过拟合：看曲线，再决定怎么改

现象常见原因可以怎么试
欠拟合：train loss 和 valid loss 都高，目标任务也差模型/训练步数不足、学习率不合适、数据与目标不匹配、序列被截断、bug 或标签错位先核对数据和 loss；增加训练步数或模型容量；调学习率与调度；改善覆盖；检查上下文和标签 mask
过拟合：train loss 持续下降，valid loss 停滞或回升；训练样例好、留出/新表达差模型相对数据过大、重复样本多、训练过久、数据泄漏/分布偏窄数据去重并扩充多样性；早停并保存最佳 valid checkpoint；增加合理正则；降低训练轮数/学习率；做真正独立的 OOD 测试
两边 loss 都下降但任务失败通用 next-token loss 与目标能力不一致；评测方式、prompt 或解码不合适；关键例子覆盖不足检查任务样例和目标格式；补针对性数据；做错误分类与 ablation；报告能力指标而非只报告 loss

每次只改变少数变量并保留基线。例如先验证训练标签对齐，再调学习率；先消除重复泄漏，再判断模型容量。不要用训练集准确率选择最终模型，也不要因单个成功例就宣称泛化。

12. 课程小结与动手路线

  1. 能画出文本 → token IDs → embedding/位置 → Decoder blocks → logits → 下一个 token 的数据流。
  2. 能解释 Q/K/V、causal mask、多头分组、上下文窗口与 KV cache。
  3. 能用配置估参数，用本机 pilot 测吞吐和峰值显存，再估总时间。
  4. 能准备去重且无泄漏的数据划分，区分训练 loss、验证 loss 和目标任务泛化。
  5. 遇到欠拟合或过拟合时，先诊断证据再改数据、模型或训练策略。
