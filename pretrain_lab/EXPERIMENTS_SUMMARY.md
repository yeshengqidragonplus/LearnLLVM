> 本文档是 v1~v8.3 全部实验的结论存档。旧脚本/数据/模型/日志已按用户指示清理，
> 本文档与核心训练脚本（03/04l）保留，作为 v9（现代数学架构路线）的对照基线与经验库。
> 实验时间：2026-09；架构：Qwen2 缩小版 65M（hidden=384, layers=4, heads=8, BF16）；
> tokenizer：Qwen2 现成（vocab 151646，多位数逐位切分）。

## 二、好的点（可复用的成功经验）

### 1. 任务标记消除通道污染（v7.2 确立）
裸 prompt `7` 的 next-token 被高频任务（比较句/算式）压死（`7`→`+` p=0.45）。
加任务标记 `后继 a a+1。` 后，标记通道与比较句/算式完全不共享前缀，歧义从根上消除。
**结论：多任务数据集必须给每个任务独立标记，否则低频任务被高频任务压死。**

### 2. 挖洞协议（held-out）区分"记忆"与"规则"
删除末位 7 的 3/4 位数全部后继样本（9 种写法 + CoT 全查），训练后洞内 100%
=> 学的是规则不是查表。**任何"模型学会了 X"的结论必须过挖洞测试。**

### 3. BPE 陷阱清单（血泪换来的格式规范）
- `=-` 合并 → 负结果写 `= -X`（等号后空格）
- 空格+负号合并 `Ġ-` → 负数后继 prompt 不能加尾空格
- 多位数逐位切分（`357`→`3`,`5`,`7`）→ 位值递推在表示层可行
- **任何新格式必须先跑 tokenizer 预检**（check_tok_*_tmp.py 模式）

### 4. 评估 prompt 前缀一致性自检（防假测试）
`tok.encode(完整训练样本)[:len(prompt_ids)] == prompt_ids` 不通过就报错退出。
v7.2 的 04h [A] 项把答案喂进 prompt 报了假 100%——这个自检杜绝此类脚本 bug。

### 5. 课程学习续训有效（v8.2 验证）
从 v8 续训（lr=5e-5，小 6 倍防冲毁）：旧能力零退化（v7.2 回归 30/30），
新宽度叠加学会（4/5 位 100%）。**续训必须小 lr + 旧任务回放数据。**

### 6. 位值公理数据高效（v8.2 验证）
[P1] 位权阶梯 / [P2] 分解 / [P3] 合成 / [P4] 位值问答——公理化数据把宽度墙
从 3 位推到 5 位，比 v8.1 纯加量（未训练）路线高效得多。
**公理（定义性知识）比例子（事实性知识）的泛化效率高——这是 v9 路线的直接依据。**

### 7. 训练工程参数（8GB 显卡实测）
- no-pack 模式 batch=16 + **长度分桶**（长短样本混批 padding 浪费 3 倍算力）
- batch=32/64 会 OOM（长 CoT 样本 ~90 token）
- 8 epoch 收敛（epoch 5 后趋平），约 2 小时/29 万条

## 三、坏的点（失败与根因）

### 1. 直接映射通道的宽度墙是架构性的（核心发现）
固定前向深度（4 层）下，"复制前缀+改末位"电路的宽度 = 训练最大宽度。
数据铺到 5 位墙就在 6 位（`515950`→`51591` 丢首位，与 v8 的 4 位失败同构）。
**墙不会消失只会移动——突破它必须换通道（CoT/算法），不能加数据。**

### 2. CoT 组装解耦（v8.2 最深刻教训）
CoT 步骤算对（`个位7+1=8`）但答案另起炉灶（抄回 `6617`）——
**答案 token 与步骤结果之间没有因果链**，模型把 CoT 当装饰、答案走查表。
根因：v8.2 CoT 格式里最终答案与步骤无 token 级依赖。
v8.3 的解法（尾挂位值合成：答案=显式执行 `4×1000+...=4484`）已设计未验证。
**教训：CoT 数据设计必须让答案的每个 token 在前文有显式来源。**

### 3. 进位链受深度限制（4 层 ≈ 3 步工作记忆）
`4999+1` 三步进位链在第 3 步断，`99999+1` 崩溃。串行状态跟踪超过 3 步不可靠。
已设计未验证的解法："数 9 格式"（末尾连续 9 一次数出，进位变 O(1) 模式识别）。

### 4. 负数 CoT 算法混淆
负数后继 = 绝对值递减（借位），模型有时用 +1（`-53201`→`个位10+1=1`）。
负数样本占比 25% 不够，v8.3 提到 41%（未验证）。

### 5. 六位数读位失败（位值提取也宽度绑定）
`321294` 读个位读成 2——P4 位值问答只训到 5 位，提取电路 6 位失效。
v8.3 加了 6 位采样 3000 条（未验证）。

### 6. 自发认识路线效率低（路线级结论）
让模型从算术事实自己归纳数轴结构：v7→v8.2 走了 6 个版本才到 5 位，
且墙仍在。**用户决策：转向现代数学架构（集合/群/公理）路线——v9。**

## 四、方法论教训（脚本工程）

1. **数据生成自检三件套缺一不可**：关键样例命中（动态生成，不手写）、
   泄漏检查（9 种写法）、CoT 数学正确性抽检（200 条）。v8.3 连抓 3 轮 bug
   （负数 CoT 方向反 / 挖洞误拦位值分解 / [H][I][E] 漏拦洞）。
2. **apply_diff 大段重写易误匹配**——改完必须读回验证（v8.3 [H] 拦洞
   diff 报成功实际没生效，靠泄漏检查抓回）。
3. **一次性诊断脚本（check_*_tmp.py）是最高效的调试形态**：
   完整输出失败样例 → 人工分类失败模式 → 对症设计。
4. **评估必须区分 L1（训练内）/L2（挖洞）/L3（外推）三层**，
   混在一起报分数 = 测的是记忆不是能力。
