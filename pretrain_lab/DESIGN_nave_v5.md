## 0. 为什么现在必须上 NAVE（v4-A 的证据）

### 决定性证据
```
问: 抄写 4483\n答:   → 4483   ✅ 4 位
问: 抄写 94692\n答:  → 9492   ❌ 5 位丢位（第 3 位 6 消失）
```
**连纯复制都做不到 5 位** → 复制通道是定宽电路（训练 1~4 位 → 只能复制 4 位）。

### 三层结构（修正 v3 的单层假设）
```
表象：位数不可知（循环上界 k 输出错）
  ↑
中层：绑定行复制丢位（数列 L := 9,4,6,2）
  ↑
底层：复制/读取通道是【定宽电路】
```

### 已排除的两条路
| 方案 | 结果 | 结论 |
|---|---|---|
| 数据侧：循环计数格式（v3） | 5 位 0% | 墙移动（绑定行仍是复制） |
| 数据侧：数位数层（v4-A） | 5~8 位 0~16.7% | **数位数第一步就是复制**，同样被挡 |

**两条数据路都撞在同一堵墙** → 必须动**表示层**。

## 1. 核心思想：值在潜空间，不在 token 串

### 用户洞见（2026-09-19）
> "大模型应该在潜空间是知道的……有点像'道可道非常道，名可名非常名'——
> 表意向量可能不能准确指向'1'，但应该在潜空间包含了数字的关系。"

**精确化**：
- **"名"**（token `1`）= 可道的、有限的符号
- **"实"**（潜空间向量）= 关系性的结构（携带 1+1=2、1<2、s(0)=1…）
- v1~v4 的做法：**给"名"，期待长出"实"** → 只学到 token 序列模式，没学到"值"本体
- NAVE 的做法：**直接注入"实"，让"名"依附"实"**

### 为什么能破复制墙
```
现在的困境（v4-A）：
  要输出 94692 → 必须"抄" 5 个 token → 定宽电路 → 失败

NAVE 之后：
  值 94692 已在潜空间（一个向量，不需要抄）
  要输出第 i 位 → d_i = (v ÷ 10^(i-1)) mod 10   ← 这是【运算】不是【复制】
```
**"从值取位"是算术运算（除/取余），作用在一个位置的表示上，不需要跨 N 个 token** → 可能绕过定宽电路。
**⚠️ 这是假设，需实验验证**（见 §7 判据）。

## 2. 用户洞察二：科学计数法解决"位权上限"

### 问题：查表式位权有硬上限
```python
place_emb = nn.Embedding(8, hidden)   # 只 8 槽 → 只能表示 8 位数
```
阿伏伽德罗常数 `6.022×10²³` 需 23 次方位 → 超限。且无法表示小数（负次幂）。
**这与用户批评"位名有尽头"是同一类问题**：查表编码必然有边界。

### 用户洞察
> "我们认通过科学计数法，能写出来并认知到很大的数比如阿伏伽德罗常数，
> 这么大的数一样可以做运算……有个拆解规则，有运算规则我们就能运算。"

```
6.022×10²³  =  [6,0,2,2]  ×  10^23
                └──┬──┘       └─┬─┘
                尾数（4 位，     指数（23，小整数）
                在槽内 ✅）       ← 关键：不需要 23 个槽
```

**大数被分解成两个都在范围内的部分** → `10^1000` 也只需指数 1000。

### 技术修正：指数用**连续编码**（RoPE 式），不用查表

| | 查表式（原 v2 设计） | **连续式（v5 修正）** |
|---|---|---|
| 位权/指数 | `place_emb[i]`，8 槽 | `place_encode(k) = [sin(θ_j·k), cos(θ_j·k)]_j` |
| 范围 | 固定（8） | **任意**（k = 23, 1000, ...） |
| 参数 | 8 个向量 | **0 个**（固定三角函数） |
| 外推 | ❌ | ✅（角度是 k 的连续函数） |

**RoPE 正是为解决"位置不能外推"发明的**（大模型位置编码的成熟方案）。
用同样的技巧编码"指数/位权"，得到**参数 O(1) + 范围无限**。

## 3. 值编码器设计（e_val）

### 3.1 完整形式

```python
def e_val(x, mantissa_digits, exp10):
    """
    x 的科学计数法分解：
      mantissa_digits: 尾数数字序列（低位在前），如 6.022 → [2,2,0,6]
      exp10:           十进制指数，如 23
    编码：
      尾数：Σ_i ( digit_emb[d_i] + place_encode(i) )
      指数：exp_encode(exp10)          ← 连续（RoPE 式）
      合成：proj(尾数编码 + 指数编码)
    """
    m = sum(digit_emb[d] + place_encode(i) for i, d in enumerate(mantissa_digits))
    e = m + exp_encode(exp10)
    return proj(e)          # proj 零初始化
```

### 3.2 三个组件

| 组件 | 参数 | 作用 | 范围 |
|---|---|---|---|
| `digit_emb` | 10 × hidden | "数字 d 是什么" | 固定 10 |
| `place_encode` | **0**（三角函数） | "第 i 位权多少" | **任意 i** |
| `exp_encode` | **0**（三角函数） | "10 的多少次幂" | **任意 k** |
| `proj` | hidden × hidden | 翻译到 token 嵌入空间 | — |

**合计参数 ≈ 10×384 + 384×384 ≈ 0.15M**（对 65M 模型可忽略）——**与"数字有多少个"无关**。

### 3.3 为什么可外推（关键）

```
11962 = 1×10^4 + 1×10^3 + 9×10^2 + 6×10 + 2
       └──────── 每一项都是训练见过的 ────────┘
       （digit_emb[1..9] 都在 10 槽内；place_encode(4) 由三角函数算出）

训练外的新数 = "旧零件的新组合"（加法组合）→ 可外推
```

**对照**：
| 方案 | 训练外的大数 |
|---|---|
| MLP 直算 `MLP(标量 v)` | 标量超出训练范围 → 输出乱码 ❌ |
| 查表 `embed[v]` | 没有对应参数 ❌ |
| **NAVE 组合** | 多一位只是多一项 ✅ |

## 4. 因果安全（继承 v2 设计，必须遵守）

### 问题
自回归从左到右读。读 `11962` 第 1 位 `1` 时，**不可能知道**完整值是 11962（未来未知）。

### 解法：NAVE-prefix（只注入"已出现数字构成的前缀值"）
```
pos: 1    1    9    6    2
v:   1    11   119  1196 11962   ← 注入前缀值
```
- 因果安全：`v_prefix` 只由**已出现**的数字决定
- 训练/推理同一规则（prompt 与逐 token 生成都成立）
- 数字串末位处，前缀值 = 完整值 → 后续生成可经注意力读到"整值"

### 防泄漏单测（必须先过，否则不出训练）
1. **因果性**：把 t 之后的 token 改写，断言位置 ≤ t 的 `v_prefix` 不变
2. **范围**：`11962` → `[1,11,119,1196,11962]`
3. **边界**：`0`、连续串、非数字夹断、串尾数字
4. **与关闭 NAVE 对拍**：手写解码循环 vs `model.generate` 应完全一致

## 5. 运算规则（科学计数法下的算法）

| 运算 | 普通表示 | **科学计数法** | 难度变化 |
|---|---|---|---|
| **乘法** | 逐位乘 + 错位加（复杂） | **尾数相乘 + 指数相加** | ⬇️ **极简** |
| **加法** | 逐位加 + 进位 | **对齐指数 → 尾数加** | ⬆️ 需对齐 |
| **比较** | 逐位比 | **先比指数，再比尾数** | ⬇️ 更简单 |

### 加法示例
```
6.022×10^23 + 3.0×10^20
→ 比较指数 23 vs 20 → 差 3
→ 小的移位：3.0×10^20 = 0.003×10^23
→ 尾数相加 6.022 + 0.003 = 6.025
→ 结果 6.025×10^23
```

**关键观察**：对齐的本质是**比较指数**——而我们的序关系在 v1~v4 **一直 100%（宽度无关）**！
→ **科学计数法的加法，复用我们已证可靠的能力（序关系）**。

### 必须诚实的边界
| 场景 | 科学计数法 |
|---|---|
| `6.022×10^23`（量级大、有效数字少） | ✅ 优雅 |
| `123456789012345678901`（精度要求高） | ⚠️ 尾数 21 位 → 又回复制墙 |

**适用边界**：大数量级 ✅ ／ 高精度长尾数 ⚠️。对当前实验（1~9 位）两种都覆盖。

## 6. 实现方案

### 6.1 新增 `nave.py`
```python
class NumberValueEncoder(nn.Module):
    def __init__(self, hidden, n_theta=8):
        self.digit_emb = nn.Embedding(10, hidden)
        # 位权/指数：连续编码（无参数）
        self.register_buffer("theta", 1.0 / (10000 ** (torch.arange(n_theta) / n_theta)))
        self.proj = nn.Linear(hidden, hidden, bias=False)
        nn.init.zeros_(self.proj.weight)     # 零初始化：起点等价于无 NAVE

    def place_encode(self, k):               # k: 位置/指数（可为大整数）
        ang = k.unsqueeze(-1) * self.theta   # (..., n_theta)
        return torch.cat([ang.sin(), ang.cos()], -1)   # (..., 2*n_theta)

    def encode(self, prefix_value):          # 因果安全的前缀值
        ...  # 逐位分解 + 组合 + proj
```

### 6.2 训练脚本（03）改动
1. `import nave`；新增 `--nave` 开关（**默认关** → 对照组不受影响）
2. 编码器挂到 model 上（`model.nave = enc`）→ 优化器/save/load 自动覆盖
3. 训练/评估把 `input_ids` 换成 `inputs_embeds = embed_with_nave(...)`
4. **不改**既有分支语义；`--nave` 关闭时与 v4-A 训练完全一致（保证可复现对照）

### 6.3 评估脚本（04e）改动
- **不能**用 `model.generate`（新 token 走内建 embed_tokens，不注入 NAVE → 与训练不一致）
- 改**手写贪心解码循环**（~25 行，带 KV cache）
- 先用"关闭 NAVE 的手写解码 vs `model.generate`"对拍，应完全一致

## 7. 实验设计（核心：验证"取位运算"能否替代"复制"）

### 7.1 对照组

| 组 | 数据 | 结构 | 目的 |
|---|---|---|---|
| **C0** | v4-A 数据 | 无 NAVE | 基线（已有：5 位 0%） |
| **C1** | v4-A 数据 | **+NAVE** | **架构单独能否破墙（核心假设）** |
| **C2** | v4-A + 取位行 | +NAVE | 组合（若 C1 有信号但不够） |

### 7.2 关键探针（新增）

| 探针 | 内容 | 判据 |
|---|---|---|
| **copy probe** | `问: 抄写 94692\n答:` | 4 位对 / **5 位对 = 破墙** |
| **取位 probe** | `问: 94692 的第 3 位是几?\n答:` | 5/6 位都对 = **取位运算成立** |
| **宽度扫描** | 4/5/6/7 位后继/加法 | 5 位 ≥60% = 破墙 |
| **数轴几何** | `cos(e_val(v), e_val(v+1))` | 远高于随机基线 = 值表示形成邻近性 |
| **科学计数法** | `6.022×10^23` 类 | 尾数/指数分解正确 |

### 7.3 判据（提前定好，避免事后找理由）

| 结果 | 结论 | 下一步 |
|---|---|---|
| C1 在 copy probe 5 位 ≥60% | ✅ **值嵌入破墙成立** | 进 C2 组合优化 |
| C1 有信号但不足（20~50%） | ⚠️ 部分成立 | 加取位行（C2） |
| C1 ≈ C0（仍 0%） | ❌ 读的问题不在表示层 | 转"化简不搬运"数据方案 |

### 7.4 数轴几何度量（验证"潜空间认识数"）
```python
# 训练后测：
cos(e_val(11962), e_val(11963))        # 应很高（相邻数相近）
e_val(11962) - e_val(11961)            # 应 ≈ e_val(1000) - e_val(999)（差值模式一致）
```
**这直接检验用户的核心命题："潜空间是否真的包含了数字的关系"**。

## 8. 风险与预案

| 风险 | 预案 |
|---|---|
| 零初始化导致 NAVE 长期不激活 | 监控 `proj.weight` 范数与 `e_val` 输出 cos 相似度；必要时 xavier 初始化 |
| 注入干扰非数字 token（`×1000` 里的 1000） | 可裁剪乘法上下文；先统一注入观察，有害再裁剪 |
| 手写解码循环有 bug | 与关闭 NAVE 的 `generate` 对拍（应完全一致） |
| **"取位运算"仍受 4 层深度限制** | 属已知边界；NAVE 只解"读/整体"，不承诺解"长进位链" |
| 科学计数法加法需对齐（新难点） | 复用已证可靠的序关系（100% 宽度无关） |
| 8 层深度限制仍在 | 已知边界；NAVE 不承诺解决 |

## 10. 与"化简不搬运"数据方案的关系（不互斥）

用户原设计（"化简不搬运"）与 NAVE 是**互补的两条路**：

| | 化简不搬运（数据侧） | NAVE（表示层） |
|---|---|---|
| 做法 | 数字留在输入，下标查读（`a_1=2`） | 值注入潜空间 |
| 依赖 | 位置注意力能否跨长度 | 取位运算能否替代复制 |
| 风险 | 位置注意力可能也定宽 | 4 层可能做不了除/取余 |
| 成本 | 低（只改数据） | 中（改架构） |

**建议**：先做 NAVE（C1），因为：
1. 它同时解决**输入侧**（读）和**输出侧**（取位）——覆盖面更大
2. 数据可复用 v4-A，成本更低
3. 若 C1 失败，再试"化简不搬运"（那时已知位置注意力是否可用）

**两者也可组合**：NAVE 提供值表示 + 化简不搬运提供结构化推理链。
