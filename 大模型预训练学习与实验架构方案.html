1实验定位与目标

目标不是产出可用的产品模型，而是完整跑通一条大模型训练链路：看懂每个环节做什么、输入输出是什么、痛点在哪里。

模型规模
~5.5M 参数
数据集
400 句 / ≈4800 token
训练方式
全量训练
显存需求
<< 8G
核心口径：走流程、做实验、看现象。极小数据集必然过拟合，这是预期现象、不是 bug——正是要亲手观察的「学习信号」。

讨论中确认的几条原则：

  • 采用小参数量模型 + 小数据集做演示实验，大计算需求（如全量大模型预训练）留给 AutoDL 云端。
  • 实验输出：训练日志、完整模型权重、推理测试输出、评估分数（train_loss / eval_loss）。
  • 学习的是大公司验证过的最新工业技术，不学脱离生产实际的老旧方案。

3关键技术选型决策（含理由）

3.1 架构选型：Decoder-Only（三选一）

架构代表预训练任务优点缺点结论
Decoder-Only（因果自回归）GPT / Llama / Qwen / Mistral下一个 token 预测生成能力最强；架构简单；工业界通用大模型全部采用；推理部署简单长上下文成本高；理解弱于 Encoder✅ 我们选这个
Encoder-OnlyBERT掩码填空 MLM理解强，适合分类/语义检索不能直接做自由生成不选
Encoder-DecoderT5 / BART去噪、序列到序列擅长翻译、摘要同参数下通用生成弱；推理链路复杂不选
理解要点：Decoder-Only 就是「因果自回归」架构 —— 每个位置只能看到它自己及前面的 token（因果掩码），绝看不到未来。预训练任务叫 CLM（Causal Language Model）：架构是「网络长什么样」，CLM 是「拿什么目标去训练」。

3.2 Dense（稠密） vs MoE（混合专家）：选 Dense

讨论澄清了一个关键误区：现代大厂不是全部用 MoE，Dense 和 MoE 是两套并行生产路线，MoE 不等于最新、Dense 不等于过时。

Dense 稠密（标准 FFN）· 主实验选型

  • 每个 token，全部 FFN 参数参与计算。
  • 代表：Llama3 全系、Qwen2.5/3 中小底座、Mistral-7B/14B、Claude Opus。
  • 训练稳定，无路由/负载均衡坑，loss 曲线干净好调试。
  • 微调、SFT、DPO 链路成熟；单卡消费级 GPU 可跑，无需多卡通信。
  • 7B~30B 底座、企业底座、私有化部署、垂直领域依然是 Dense 主流。

MoE 混合专家 · 后续对照实验

  • 只替换 FFN：拆成 N 个专家 + 门控 Router，每个 token 选 top-K 专家。
  • 代表：Mixtral、DeepSeek-V2/V4、Qwen-MoE、Llama4 Scout。
  • 不是省显存，是省 FLOPs：所有专家权重常驻显存，显存开销巨大。
  • 必须加负载均衡 aux_loss，否则「专家坍缩」。
  • 极小数据集几乎无法产生专家分工；公开有效 MoE 基线激活参数普遍几百 M 以上。
结论：MoE 不是用来做 5M~几十 M 小模型玩具预训练的技术。本次主实验用 Dense Decoder-Only Transformer（= 把 Llama/Qwen 工业架构做缩小版）；MoE 留到完全理解 Dense 之后做「只替换 FFN」的对照实验。

3.3 Decoder-Only 内部组件选型（全部对齐现代大厂标准）

组件工业标准（Llama3/Qwen2）我们选型说明
整体架构Decoder-Only Transformer同左去掉 encoder、去掉 cross-attention，只堆叠 Decoder Block

为什么不用量化做预训练

关键点：4-bit/8-bit 量化不能用于全量预训练，只能用于推理或 LoRA 微调省显存。预训练主流是 BF16。本实验 5.5M 参数全量 BF16 显存远小于 8G，根本不需要量化，也不需要 LoRA。

4核心概念学习记录

以下为讨论中逐步确认的学习要点，作为知识沉淀。

4.1 什么是「自回归」（Auto-Regressive）

「自回归」= 用序列自己过去的结果，预测下一步。数学上就是条件概率公式：

P(xt | x1, x2, …, xt-1)

每一步预测只依赖该序列自身前面已生成的历史，所以叫「自」回归。

  • 训练阶段：手里有完整文本，靠因果掩码一次性并行算全部位置 loss —— 工程并行加速，任务本身仍是自回归。
  • 推理阶段：逐 token 迭代 —— 把上一步模型自己输出的 token 拼回输入，再预测下一个。输入来源于模型自身过去的输出，这才是「自回归」最直观的体现。
易错点：「自回归」≠「只能一个 token 一个 token 跑」。推理必须逐 token；训练可并行，是工程优化。

4.2 条件概率公式拆解（P(xt | x1…xt-1)）

  • x：一个 token；下标 t：序列第 t 个位置。
  • xt：想预测的第 t 个 token；x1…xt-1：它前面已出现的 token。
  • 竖线「|」：条件符号，读作「已知 / 给定」。
  • 整句翻译：已知前面已有 x1…xt-1，求下一个是 xt 的概率。

整句概率 = 各步条件概率连乘：

P(x1,…,xT) = ∏t=1..T P(xt | x1,…,xt-1)

4.3 交叉熵（Cross-Entropy）—— 预训练的 loss

用来衡量模型预测的概率分布和真实答案的差距。数值越小 = 猜得越准；越大 = 猜得越离谱。

H(p,q) = −∑ pi log(qi)　→　CE = −log(qtrue)
  • 真实标签是 one-hot（正确 token 概率=1，其余=0），求和后只剩一项。
  • 例：真实答案是「二」，模型给「二」0.9 → CE≈0.105（好）；给 0.25 → ≈1.386（一般）；给 0.01 → ≈4.605（差）。
  • 为什么不用准确率：准确率只判断是否命中；交叉熵会惩罚「给正确词信心不够」，梯度信息更丰富。
  • PyTorch 的 CrossEntropyLoss 内部自带 softmax，直接传 logits 即可。
  • 预训练对序列每一个 token 都算交叉熵、取平均；SFT 只对 assistant 回答部分算 loss。

4.4 hidden_size（隐藏维度）是什么、为什么取 256

每个 token 经过 Embedding 后变成一个数字向量；hidden_size = 这个向量的维度。例如 hidden_size=256，每个 token 就是 256 个浮点数组成的向量，代表它在模型内部的语义表示。所有层（注意力、FFN）都在对这一组向量做变换。

  • hidden_size 越大 → 表达能力越强，但参数量近乎平方上涨、显存变大；小数据集下容量过剩 → 直接过拟合、死记样本。
  • hidden_size 太小 → 装不下足够特征 → 欠拟合，loss 降不下去。
  • 为什么 256：本实验 400 句/≈4800 token，数据极小。128 太小（中英混合装不下）、512 偏大（更快过拟合）。256 平衡表达能力，且 256 ÷ 4 头 = 64，正好是行业经典的 head_dim=64。
硬约束：head_dim 尽量保持 64；hidden_size 必须能被注意力头数整除，否则代码直接报错。

4.5 num_hidden_layers：为什么把多个 Decoder Block 套在一起

每一层 Block = 一轮更深层次的理解：浅层抓简单局部关系，深层抓复杂、远距离的关系。一层 Decoder 能力会非常弱。

图 4-1　Decoder-Only 架构堆叠示意（num_hidden_layers=3）：3 个结构相同、权重独立的 Decoder Block 串行堆叠（示意）
  • 每个 Block 内部两件事：注意力（找词与词关系）+ FFN（对每个 token 做非线性变换、提炼特征）。
  • 为什么不是越多越好：层数太多 → 参数变多更容易过拟合、深层网络容易梯度消失/爆炸导致训练震荡。工业大模型敢堆 24~64 层，是因为有海量数据 + RMSNorm/残差/warmup 稳住训练。
  • 残差连接（输出 = 输入 + 处理结果）保证原始信息能一路后传，这是能堆多层的关键。

4.6 多头注意力 vs 多层 Decoder：两者的区别

这是讨论中一个经典混淆点：

多头注意力（num_attention_heads）

同一遍思考里，多双眼睛从不同角度看。在单个 Block 内部，把向量切多份交给多个头：头1 看主谓、头2 看修饰、头3 看时序……各头算完拼回来。

局限：只做「观察、建立词与词关联」，不能迭代升级语义。

多层 Decoder（num_hidden_layers）

完整思考流程重复多轮，迭代加深理解。第 1 层输出初级理解 → 第 2 层在已加工语义上再找深层关系 → 第 3 层看到整句逻辑。

关键：第 2 层注意力看的不是原始文字，而是第 1 层处理后的向量。

记忆口诀：多头注意力 = 一遍思考、多双眼睛看；多层 Decoder = 看完一遍、再完整思考好几遍。多头负责多角度观察，多层负责迭代加深理解，两者互补、不可替代。

5训练目标与规模评估方法

开工写代码前必须先回答三个问题：① 训练目标怎么定、怎么评估；② 预训练数据规模（多少 token）怎么评估；③ 模型参数规模怎么评估。本章即讨论中「先做方案设计、再动手」的方法论沉淀。

5.1 训练目标如何评估

维度结论说明
预训练学什么语言本身的分布词/子词表示、语法、事实、逻辑、next-token 概率；不是学「回答问题」
训练目标（损失）因果自回归 next-token 预测的交叉熵全部 token 参与、无 mask；SFT 才会 mask user 部分
用什么指标评估train_loss + eval_loss预训练没有准确率、不做人类打分、不做对话评测（那是 SFT 之后的事）
loss 下降 = 在学train_loss 持续下降模型在拟合文本分布
过拟合拐点eval_loss 先降后升极小数据集几乎必然；eval_loss 最低点 = 泛化最好的 checkpoint
一句话标准：训练目标不是「让模型变聪明」，而是loss 平稳下降、且你能读懂 loss 曲线每一段的含义（下降 = 在学、拐点 = 过拟合、震荡 = 超参问题）。

5.2 预训练数据规模（大小）如何评估

第一步：把数据规模统一换算成 token 数（不要用「句数/字数」——模型算力与显存都按 token 计）。

总 token ≈ 样本条数 × 平均每样本 token 数
  • 粗估：先用 tokenizer 编码几条样本看平均长度，再乘总条数。例：400 句（200 中 + 200 英）× 平均 12 token/句 ≈ 4800 token。
  • 精确：预处理时用 len(tokenizer.encode(text)) 逐条统计，得到真实总数。

第二步：用 Chinchilla 定律判断「数据够不够」。工业最优配比约 1 个参数配 20 个训练 token（适合大数据集）。

  • 我们 4800 token 的「最优参数」≈ 4800 ÷ 20 = 240 个参数 —— 现实中不存在，说明数据量远低于工业最优。
  • 核心判断：数据规模决定模型能做多大，而不是反过来。数据不足时模型容量必须压小（宁 5.5M，不可 100M），否则直接背样本、瞬间过拟合。

5.3 参数规模如何评估

  • 容量匹配原则：容量过剩（参数过多）→ 死记硬背 → 过拟合；容量不足（参数过少）→ 特征装不下 → 欠拟合。
  • 小数据经验：优先加宽 hidden_size，不要盲目堆层数（矮胖优先于高瘦）；层数太深在数据少时易震荡、更快过拟合。

粗略核验公式（估算口径，非精确）：

参数量 ≈ 9.3 × 层数 × hidden_size² ＋ vocab_size × hidden_size（Embedding/LM-Head 共享只算一份）
  • 代入本实验：9.3 × 3 × 256² ≈ 1.83M；＋ 16384 × 256 ≈ 4.19M → 合计 ≈ 6.0M，与讨论确认的 ~5.5M 同量级 ✅。
  • 用途：改完配置立刻估算参数涨跌，不用等代码跑完。

6实验方案定稿（主实验）

方案一句话：200 句中文 + 200 句英文短句（≈4800 token），从零随机初始化一个 Dense Decoder-Only Transformer（约 5.5M 参数），全量 BF16 预训练，跑通完整链路并观察 loss / 过拟合现象。

vocab_size16384中英混合；若复用 tokenizer 则跟随其 vocab_size

6.4 显存估算（BF16 全量预训练）

预训练显存 = 模型权重 + 优化器状态 + 梯度 + 激活值。全量训练时优化器状态是大头。

图 6-1　显存构成估算（示意，比例不精确）：权重 ~11MB + 优化器 ~44MB + 梯度 ~11MB + 激活值（随 batch/seq_len 变化）数百 MB
  • 权重显存 = 参数 × 精度（BF16 = 2 字节/参数）→ 5.5M × 2 ≈ 11MB。
  • AdamW 优化器状态：每参数 8 字节（内部保存 FP32 的动量+方差两份）→ 5.5M × 8 ≈ 44MB。
  • 梯度：与权重精度相同 → ≈11MB。
  • 激活值：与 batch、seq_len 强相关；本实验 seq_len=512、batch=2，约几百 MB。显存不够时开 Gradient Checkpointing（省激活显存、代价是变慢）。
  • 一旦模型到 B 级别，优化器状态直接 GB 起跳 —— 这正是大模型全量训练吃显存的核心原因之一。

6.5 训练时长估算

FLOPsstep ≈ 6 × N × batch_size × seq_len × hidden_size²
  • 每步 FLOPs 乘 6（一次前向 ≈ 2 倍反向，反向约 2×前向，合计约 6×）。
  • 单步时间 = FLOPsstep ÷（实际算力 TFLOPS × 10¹²）；GPU 实际利用率一般只有 20%~40%。
  • 总步数 = 总训练 token ÷（batch_size × seq_len）；总时间 = 总步数 × 单步时间。
本项目量级（估算）：总训练 token ≈3840、batch×seq=2×512=1024，总步数仅约几十步量级，训练时间预计分钟级以内。对比工业界：万亿 token、上万 GPU 训练数月。

6.6 预期观察现象（实验记录要点）

  • train_loss 稳步持续下降。
  • eval_loss 前几个 epoch 下降，到达最低点后开始上升 → 过拟合。
  • eval_loss 最低点对应的 checkpoint = 模型泛化能力最好的权重；之后模型在死记 400 句训练文本。
  • 推理测试：训练前随机初始化输出乱码；训练后倾向复现训练文本里的数学等式、单词翻译；未见过的句子依旧很差（完全正常）。

7预训练完整流程（分步）

1
定义预训练任务与玩具数据集

任务：因果自回归 next-token 预测。数据：纯文本 jsonl（{"text":"…"}），无对话标记。样例：「一加一等于二。二加二等于四。苹果 apple。香蕉 banana。」多复制凑几十~数百条。

2
Tokenizer（预训练里极其关键）

完整工业流程是先自己训练 tokenizer 再训模型；个人实验复用现成 tokenizer（记录：真实工业这里是一步独立训练）。工作流：字符串 → 子词 token → 整数 id；截断到 max_seq_len；Packing 拼接。tokenizer 和模型强绑定：vocab_size 变了，LM-Head / Embedding 维度必须同步改。

3
模型初始化（真正从零预训练的起点）

只定义结构配置，不加载任何预训练权重，全部随机初始化。例如 Qwen2Config(hidden_size=256, num_hidden_layers=3, …) + Qwen2ForCausalLM(config)。⚠️ 这里是随机初始化骨架，不是下载 Qwen-0.5B-Base 权重，这才是「从零预训练」。

4
数据集预处理流水线

对每条 text：tokenizer 编码 → 截断到 max_seq_length →（预训练一般用 packing，不 padding）→ 生成 labels（直接复制 input_ids，不做任何 mask）→ 拆 train / validation。

5
训练循环（预训练 loss 计算）

核心：labels=input_ids，模型自动移位（用 input_ids[:, :-1] 预测 labels[:, 1:]）。预训练不 mask 任何 token 的 loss，全部位置都算 —— 这是和 SFT 最大区别之一。手写循环即 forward → loss → backward → optimizer.step()。

6
训练参数

AdamW；lr 比微调大（3e-4 ~ 1e-3 玩具级）；cosine + warmup（预训练必须 warmup）；梯度裁剪。观察 train_loss / eval_loss。

7
保存模型权重

定时保存 checkpoint，保存完整模型 state_dict（不是 LoRA）：model.save_pretrained("./my_pretrained_model") + tokenizer 一并保存。

8
预训练后推理验证

随机初始化未训练前：输出乱码；训练后：倾向输出训练文本里的模式。示例：prompt="一加一等于" → model.generate(...) → decode 观察续写。

关键代码要点（讨论中出现）

# 1) 随机初始化，不加载任何权重 —— 从零预训练的起点
config = Qwen2Config(
    vocab_size=16384, hidden_size=256,
    num_hidden_layers=3, num_attention_heads=4,
    intermediate_size=682, max_position_embeddings=512
)
model = Qwen2ForCausalLM(config)   # 权重全部随机

# 2) 预训练训练循环核心 —— labels = input_ids，全部位置算 loss
for batch in train_dataloader:
    out = model(input_ids=batch["input_ids"],
                 attention_mask=batch["attention_mask"],
                 labels=batch["input_ids"])   # 模型内部自动移位
    loss = out.loss
    loss.backward(); optimizer.step(); optimizer.zero_grad()

8评估策略

预训练不看「聊天效果」，主指标就是 loss。对话评测属于 SFT 之后的事。
阶段指标解读
训练过程train_loss持续下降 = 模型在拟合文本分布
训练过程（最重要）eval_loss下降 = 泛化变好；开始上升 = 过拟合（玩具小数据集几乎必然）
训练过程学习率曲线 / 梯度范数监控 warmup 与梯度爆炸
训练结束（定性）采样生成续写未训练乱码；训练后应复现训练文本模式

预训练阶段不做人类打分、不做对话评测；没有准确率，只有交叉熵 loss —— loss 越低代表下一个 token 预测越准。

11讨论问答摘录

问答 1Decoder-Only 为什么叫自回归？

「回归」= 用已知变量预测另一变量；「自回归」= 用序列自己过去的输出预测下一步。推理时上一步生成的 token 会拼回输入成为下一步输入 —— 输入来源于模型自身过去的输出，故叫「自」回归。

问答 2P(xt | x1,…,xt-1) 代表什么？

条件概率：已知前面已有 x1…xt-1，求下一个是 xt 的概率。例：「苹果好吃」，P(x3|x1,x2) = 已知「苹、果」，下一个字是「好」的概率。

问答 3交叉熵为什么比准确率更适合做 loss？

准确率只看是否完全命中（错一点不计较错多少）；交叉熵会惩罚「给正确词信心不够」，即使答案没完全错也有梯度，信息更丰富。例：都预测错时，模型 A 给「二」0.4 比模型 B 给「二」0.1 的 loss 更小，能引导优化方向。

问答 4数据集 6000 句时为什么选 384，改到 400 句为什么降到 256？

模型容量必须匹配数据量：Chinchilla 最优配比约 1 参数 : 20 token。6000 句/9 万 token 用 13M/384；400 句/4800 token 容量必须压小到 5.5M/256，否则直接背样本、瞬间过拟合。hidden_size 太小则欠拟合。

问答 5为什么 400 句数据只用 3 层、不用 8 层？

层数太深在数据极少时容易训练震荡（loss 上蹿下跳不收敛）且更快过拟合。小数据预训练经验：优先加宽 hidden_size，不要盲目堆层数；3 层足够演示完整 Transformer 机制。

问答 6MoE 改动的是 Transformer 的哪个组件？注意力层改不改？

MoE 只替换 FFN 前馈网络部分，注意力层完全不变。Dense 和 MoE 的注意力、RMSNorm、RoPE、因果掩码、Decoder 堆叠全部一模一样。MoE 不是整个换掉 Transformer，只是 FFN 的一个变种。

问答 7原始 Transformer 里的 cross-attention，Decoder-Only 里还有吗？

没有了。Decoder-Only 把 encoder 和 cross-attention 都删掉，只保留 Decoder 块堆叠 —— 这就是现在 90% 通用大模型的底座。

问答 8num_hidden_layers=1、num_attention_heads=16，核心短板是什么？

头再多也只能在原始文字层面找关系，无法迭代升级到短语、句子级语义。多头负责多角度观察、多层负责迭代加深，两者互补不可替代。
