# 指示代词 = 包引用（2026-10-21 用户洞察）

用户指出：`<|PKG_NAME|>` 和指示代词是**同一个机制**，都"指代了具体内容"。这条把一个
原本无法自动判分的难题（指代消解）变成了有限集合里的选择。

## 统一后的说法

| 现象 | 输出形式 | 本质 |
|---|---|---|
| "声明科室"这个能力 | `<|PKG_NAME|>#7` | 指向注册表里的一个条目 |
| "这两个常量" | `<|PKG_NUM|>#2 #3` | 指向包表里的两个条目 |

**都是"指向一个已存在的对象"，所以用同一套引用机制。** 这直接导出了 D6 的改动：
科室名不写明文（原建议 `<|ROUTE|> #1 声明科室`），改写成包引用 `<|ROUTE|> #1 #7`。

## 为什么这个改动重要

1. **科室可动态增加**：加科室只需注册表加一行，不用给每个科室注册新标记、不用改词表。
   写明文的话，加科室等于改变训练数据分布。
2. **输出空间封闭**：科室名从"任意中文词"缩小成"包表引用集合"，可以自动判分。
3. **代词消解不再需要单独的能力**：它和"引用一个包"是同一个操作。

## 由此产生的可测实验（§1.8.3）

指代消解以前没法量化，现在可以。三轴梯度探针，独立于完整协议：

| 轴 | 取值 | 测什么 |
|---|---|---|
| 距离 | 10/50/100/200/400 token | attention 跨度上限 |
| 干扰项数 | 2/5/10/20 | 选择性 |
| 类型混淆 | 同类型/不同类型干扰项 | `<|PKG_NUM|>` 类型标记是否真起作用 |

产出的三个数字直接决定协议参数：**投影最长能写多长**、包表要不要截断、
类型标记有没有用。所以这个实验必须排在投影格式定稿之前。
