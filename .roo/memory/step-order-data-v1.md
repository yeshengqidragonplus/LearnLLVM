# 步骤顺序语义数据 v1（2026-10-14，19_prepare_step_order_v1.py）

用户要求训练「步骤顺序语义」（"你先xxx，再xxx，然后xxx，最后xxx" 与 "第一xxx，第二xxx，最后xxx"）。**用户明确反馈：内容要围绕编程主题，不要泡茶/煮面等日常流程**——第一版用了日常流程被要求返工。

设计要点：

- 两套标记体系（副词式 先/再/然后/接着/随后/最后；序数式 第一/第二/…/最后）渲染同一组步骤，另有 convert_marker 互转样本，让模型学"两套标记=同一个顺序结构"。
- 1,466 条 / 68,629 token / 10 种样本类型：叙述、首/末步、之后/之前、位置、步数、乱序重排、标记互转、续写下一步。
- 内容：16 个手写真实开发流程（编译 C 程序、修 bug、提交、部署、训练小模型等）+ 60 条编程动作池随机组合（3-5 步）。
- 所有问答答案从 steps 列表程序化派生，审计逐条核对一致性；抽象序列的 QA 带叙述上下文前缀（自包含 + 防跨序列问句重复——第一版没加前缀时 60 条序列的"这个过程最先做什么"互相撞车触发唯一性审计）。

两个踩过的语义坑（后续写类似数据要避开）：

1. **续写样本前缀不能用完整叙述渲染器**：render_a 会给前缀末尾加"最后"，等于宣称过程已结束，再问"下一步"自相矛盾。需要专门的 render_prefix（只用 先/再/然后，绝不出现"最后"）。
2. **中间标记用 rng.choice 可重复**会生成"然后…然后"；改为不重复采样（rng.sample，超过池大小才允许重复）。

沿用 18 号的环境做法：纯 tokenizers 库统计 token（本机页面文件小，import transformers 会拉 torch CUDA DLL 触发 WinError 1455）；固定 seed=20261013 可复现，审计含重建逐字节一致与文件 sha256；训练行带 text 字段可直接喂 03 训练器。

README 3.8 节已记录；数据在 data/step_order_v1_train.jsonl（gitignore）。
