# 协议设计必须分两层：基座动作 vs 科室动作（2026-10-21）

起草 `DESIGN_protocol_v1.md` 第一稿犯的两个错误，以及修正结论。这两个错误值得记住，
因为都很容易再犯。

## 错误 1：自造 `H1`/`H4` 句柄，丢掉 `<|PKG_*|>` 标记族

第一稿设计了一套 `H<n>` 纯文本句柄，以为"更短"。实际上：

- `H1` 不携带类型，只能靠投影里的 `H1=数` 文本现学；
- `<|PKG_NUM|>` 是已注册单 token，**类型白送**；
- 更重要的是丢了 20 号已跑通的解包/审计规则，等于另起一套体系。

**结论**：包引用一律用 `<|PKG_*|>#<序号>`，例如 `<|PKG_NUM|>#3`。
标记给类型，序号只用于消歧，程序分配、模型只能引用投影里出现过的。

## 错误 2：动作表混层 → 漏了 ROUTE

第一稿 7 个动作里没有 `<|ROUTE|>`（挂号），却塞进了 `COMPUTE`/`CHECK`（科室内部怎么算）。
这不是"数量不够"，是**层没分开**。后果：协议等于"程序自己知道该干什么"，模型不参与分诊，
退回规则路由，与学习路由 63.9% 那个实验没有本质区别。

**正确分法（医院模型两层的动作实现）**：

| 层 | 动作 | 谁定 |
|---|---|---|
| 基座 | ASK / ROUTE / SPLIT / MERGE / VERIFY / OUTPUT / DONE / FAIL（8 个） | 65M 基座模型 |
| 科室 | 各科室自注册（算数：COMPUTE/CHECK；声明：GEN/EXPLAIN_DECL；…） | 科室专家或执行器 |

加科室 = 加一行注册表，不扩基座动作表、不动基座权重。

`SPLIT` 必须在基座层：拆"帮我写个网站"是问诊的一部分，不归任何科室。

## 错误 3（选例）：L1 不能重复 09 号已通过的案例

第一稿用 `1234567 + 7654321` 当 L1 两跳算术。这个算式是 09 号单列专家的实测案例
（`output_iterative_digit_v1`，200/200 状态穷举、100 位全 9 加 1 正确），**已经通过**。

真实的能力缺口排序（按"是否真没测过"，不按难度）：

| 级 | 内容 | 状态 |
|---|---|---|
| L0 | 单科室单步 | 已验证（声明 58/60） |
| L1 | **两三科室串联，package 跨科室传递** | **未测 ← 第一个真缺口** |
| L2 | 基座学习路由（不靠规则） | 未测，历史学习路由只 63.9% |
| L3 | 科室内部循环 | 已验证（09 号 200/200） |
| L4 | SPLIT 拆解 + MERGE 汇总 | 未测 |

L1 新选例：`这段代码 const int A = 1234567; const int B = 7654321; 把这两个常量加起来，用十六进制告诉我`
→ 声明科室 → 算数科室 → 进制转换 → OUTPUT → DONE，5 轮全是 ROUTE + 包引用。
