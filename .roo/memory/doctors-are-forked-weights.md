# 「医生」= 从基座续训出的独立权重，不是外挂执行器（2026-10-21，用户第二次纠正）

我曾两次把「科室专家」写成"基座权重冻结 + 外挂 Python 函数/小 MLP"。用户再次纠正，
这是他这一段时间想通的核心结论：

> **先训练一个具备沟通交流能力的小模型基座，再从它继续训练成不同专家（医生）。**
> 每个医生做不同的事，但都是从小模型基座得到的。**并不是基座权重不动。**

架构图：

```
                沟通交流基座（一个模型）
               /        |         \
          续训         续训        续训
            /            |           \
    门诊医生          声明科医生     算数科医生
    (ASK/ROUTE)       (GEN_DECL)    (COMPUTE)
```

## 这条纠正带来的三个后果

1. **协议的存在理由变了**：协议不是为了"程序能解包"，而是**不同权重的模型之间的通信标准**。
   门诊 ROUTE 给声明科时，声明科看到的是门诊写下的 `<|PKG_CODE|>#1`，那是另一个模型的输出。
   能互通，唯一保障就是都从同一基座续训 + 同一套标记。

2. **所有医生必须在同一张全局标记表里分配 ID**（`tokens.json`），不能让各医生自己 resize。
   否则门诊写的 `<|ROUTE|>`，声明科读成另一个 ID，交接当场失效。

3. **投影格式必须在所有医生训练数据里逐字一致**。投影的读者已经是不同权重的模型，
   各科室微调措辞会在训练阶段就悄悄错位，且很难从 loss 看出来。

## 现有资产按这条标准重新分类

| 件 | 算不算医生 | 说明 |
|---|---|---|
| `output_v5c1` | 基座雏形 | 数学基座，不是**交流基座** |
| `output_decl_packed_v1` | **算** | 从 v5c1 续训，58/60 |
| `output_consult_text_v1` | 算（失败） | 从基座续训，但输出与输入无关 0/27 |
| `output_iterative_digit_v1`（09） | **不算** | 8,260 参数 MLP，外挂执行器 |

因此 L1「三科室串联」里，算数科与进制转换目前只能占位，或先续训出真医生（D13 = L1-b）。

## 尚未解决的前置问题

**目标是"沟通交流基座"，但现有唯一可续训的起点 `output_v5c1` 是数学基座。**
交流能力数据（真对话、多轮澄清）目前不存在，且上次从基座续训交流的尝试是 0/27。
这条决定了"先做模板还是先做交流"这个问题的真正答案。
