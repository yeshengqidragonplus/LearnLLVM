# 原子 key 的零样本能力为零，而且是确定性错误（2026-10-23 实测）

## 结论

`<|PKG_<TYPE>|,#<ID>>` 注册后是**单个不可分 token**，它的拼写里不含类型名，
与类型标记 `<|PKG_<TYPE>|>` 之间**没有任何词形联系**。因此：

- 没进过训练集的 key，模型对它属于哪个类型**一无所知**；
- 60 条负对照（6 类型 × 10 条 `#Z`，训练中零出现）**0/60**，
  **显著低于**随机基线 1/6 ≈ 0.17；
- 错误是**确定性的**，不是随机的：每类固定映射到同一个错类，10/10 一条不差：

| 期望 | 实际输出 |
|---|---|
| `<\|PKG_NUM\|>` | `<\|PKG_ARITH\|>` |
| `<\|PKG_NAME\|>` | `<\|PKG_ARITH\|>` |
| `<\|PKG_TEXT\|>` | `<\|PKG_NAME\|>` |
| `<\|PKG_CODE\|>` | `<\|PKG_TEXT\|>` |
| `<\|PKG_ARITH\|>` | `<\|PKG_TEXT\|>` |
| `<\|PKG_TASK\|>` | `<\|PKG_NAME\|>` |

## 为什么这比「瞎猜」更危险

瞎猜会散在多个类上，能碰运气。确定性坍缩说明模型**不会对未声明的 key 表示不知道**，
而是自信地稳定输出一个错类。所以：

1. **「key 是否已注册」必须由程序校验**，不能指望模型自查；
2. 包表必须**先声明、再训练**；
3. 给医生加新 key **必须补训练**，零样本推广不成立。

这是「包做成原子整体」的固有代价，不是 bug。想换回零样本能力就得让 key 带上
可读类型线索，那等于放弃原子性 —— 两者不可兼得。

## 顺带修正的一条旧诊断

v7 里 `type_id` 留出集掉到 0.25~1.00、错误全吐 `<|PKG_TASK|>`，
当时推断是「配比不足」。v8 把 type_id 从 192/512 提到 300/672 后，
k2/k6/open 三档留出为 0.97/0.97/0.94，**推断被证实**。

同时否掉一个提案：候选枚举（k2/k6）与开集（open）只差 4 个百分点，
在每格 6 条下无统计意义 → **协议里可以要求开集输出类型标记，不必枚举候选**。

## 写这类探针的前提（否则结论不可归因）

- 留出集必须**由数据脚本分层直出**，不能依赖 `03_train_pretrain.py` 的
  `random.shuffle` 切 20%（那样每格只剩 4~10 条，且无法保证已注册 key 都进过训练）。
- 审计必须硬断言「除刻意留白的 key 外，每个已训练 key 在训练文件里出现 ≥N 次」，
  否则未出现 key 拿着随机 embedding 评估，制造无法归因的错。
- 负对照整档只能进留出集（见 `HOLDOUT_ONLY_AXES`），混进训练就退化成普通泛化。
- 逐条样本要**全量落盘**。截断前 N 条会把排在后面的轴整个截掉，事后只能看聚合分。
