# v9b 假失败根因：干扰编号连续块 = 记忆捷径（2026-10-26，v10 修复并全对）

deepseek 的 v9b（`output_probe_v9b`）留出集 semantic_pick 只有 0.46，错例全是
「类型对、编号差 ±1~2」，且错编号恰好是包表里的干扰项。v10（31 号脚本，
`output_probe_v10`）只改数据生成方式，同配置同评估器，468 条留出全 1.00。

## 根因：29 号生成器的干扰编号连续取

`cur = (cur + 1) % 400` 让包表永远是 `#297 #298 #299` 相邻块。模型记住
「指纹 → 块尾」即可拿分，不必学「读 `<|PKG_NUM|>` 后面的编号」这条 induction
规则。证据链：train 0.0206 / eval 0.3765（18 倍 gap = 纯记忆）；留出集上
induction 不精确 → 错编号全是包表内干扰项。

## v10 的三处修复（31_prepare_probe_v10.py）

1. **干扰编号等距网格采样**：随机相位 + 步长 16，包表内任意两编号差 ≥16
   （`MIN_ID_GAP`）。注意：随机拒绝采样在 20 个干扰项时会卡死（400/16=25 是
   极限），必须用网格。
2. **target 编号独立轮转**：train/holdout 各自 `counter % 400`，每编号恰好
   6~7 次作为答案被监督（v9b 平均 3 次且不保证）。LCG 打散在 3000 条里
   分布 4~8 次不均，审计会挂。
3. **每格 150→300 条**。

新增审计：`id_gap_ok`（逐条断言包表内编号互差 ≥16）、`target_id_coverage`
（每编号作为 target ≥6 次）。

## 两条通用教训（写探针数据必读）

1. **干扰项与答案在「要被区分的维度」上必须不相邻**，且要写成审计断言。
   否则模型学的是指纹不是规则，loss 上表现为 train/eval 巨大 gap，
   分数上表现为留出集崩盘。这类假失败与「机制不成立」无法从分数上区分，
   只能从数据审计上预防。
2. **监督密度按答案空间算**：401 选 1 的编号，每编号作为答案 ≥6 次才稳。
   「出现在包表里」≠「作为答案被监督」，两者分开审计。

## 顺带修正：v8 的 unseen 0/60 结论不适用于 v9/v10 形态

v9b/v10 的 `type_id_unseen`（#400 零训练）都是 **1.00**。v8 的 0/60 建立在
per-key 形态（类型+编号同一个 token）上；v9 起类型标记与编号分离，类型辨识
只需读编号前面的类型标记，与编号 embedding 是否训练过无关。deepseek 在
v9b 的 verdict 里把 1.00 写成「固有代价」是自相矛盾的。引用
`atomic-key-zero-shot-is-zero.md` 的结论时必须先确认形态是 per-key 还是分离式。
