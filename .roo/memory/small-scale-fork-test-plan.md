# 小规模分叉测试方案（2026-10-21，用户定）

用户决定：在搭整套医院架构之前，先做**两个小规模对照测试**，验证"同一基座能否分叉出专科专家"以及"硬件/规模是否够"。

- **共同基座**：现成 `output_v5c1/final_model`（Qwen2, hidden 384 / 4 层 / 8 头，embedding `[151646, 384]`，带 `nave.pt`）。
- **分叉 A：问诊专家（门诊/客服）** —— 强化沟通交流、多轮澄清、把模糊意图拆解成 Package。不负责解题。
- **分叉 B：编程专家（科室）** —— 强化编程能力；当前**会诊+治疗都由他自己做**（单体），未来才拆给调试/Unity/服务器等子科室。用户明确"具体怎么拆分还没想好"，拆分方式取决于小模型规模与硬件，因此本轮不预先设计子科室。
- 两个专家都从同一基座**继续训练**得到（不是从零）。

两个前置工程事实（已实测）：
1. `--init-from` 目前被 [`03_train_pretrain.py:230`](../../pretrain_lab/03_train_pretrain.py) 的 vocab 校验硬卡：基座 151646 vs 加三个包标记后 151649，**必须先支持 resize embeddings**（保留旧行、只随机初始化新增行）。
2. `output_v5c1` 只有 `model.safetensors` + `nave.pt`，**没有 config.json / tokenizer 副本**（`save_pretrained` 中途未完成或被清理），加载需要外部喂 tokenizer 与结构参数。详见 `.roo/memory/continue-training-vocab-blocker.md`。

判据（本轮只要求"能看出趋势"，不要求能力结论）：
- 问诊：给定模糊请求能否反问（缺槽位），澄清后能否输出结构化的 Package 请求而不是直接答题。
- 编程：声明级双向（代码⇄中文注释）严格/部分分是否显著高于随机/冒烟基线。
- 两个专家训完都要回归测数学 v5 的少量样，观察续训对基座能力的破坏程度（灾难性遗忘）。
