# 包引用编号必须用单字符，且失败原因不是编号（2026-10-22）

## 编号本身的坑（已实测）

`#1` / `#12` / `#123` 在 Qwen2 tokenizer 下：

| 编号 | token | 数 |
|---|---|---|
| `#1` | `['#','1']` | 2 |
| `#12` | `['#','1','2']` | 3 |
| `#22` | `['#','2','2']` | 3 |

**`#1` 是 `#12` 的严格前缀**，`#2` 是 `#20`/`#22` 的前缀；且 8 token 变 10 token。
这会让"编号读不准"与"候选太多"两种失败混在一起。

改用 `#A..#V`（`_ID_CHARS`）：每个都是 `['#','X']`，**等长 2 token、前缀冲突 0**。
完整条目 `<|PKG_NUM|>#A 数值(#A)` 恒为 8 token（数字编号是 8/10 变长）。

配套改动：
- 22 号加 `REF_TOKEN_RE = re.compile(r"#[A-Z]")`，audit 全部改成**正则整体抽取 + 集合比较**，
  不再用 `int()`、不再做 `startswith`/子串匹配。
- 23 号 `REF_RE` 同步改 `#[A-Z]`，`score()` 与 `target_is_at_tail()` 都改为字符串集合比较；
  B 组 `_filler` 与 target 也一并改成单字符。

## 关键结论：换字母后 22 项档没有变好

同一份 384 条数据、同一配置，只换编号方案：

| 干扰项档 | 数字编号 `#1..#22` | 字母编号 `#A..#V` |
|---|---|---|
| 2 / 5 / 10 | 1.00 | 1.00 |
| **20（22 项）** | **0.9375** | **0.9375（同分布）/ 0.50（留出 4 条）** |

**所以「包表 10 项上限」不是编号位数造成的，是真实的候选数量容量限制。**
之前怀疑是前缀/变长问题，实验否证了它。

但编号仍应改成单字符——否则这个实验**无法归因**（两个变量绑在一起）。

## 留出集（76 条，训练未见过）

- 距离轴 10~800 全 1.00
- 干扰 2/5/10 全 1.00，**20 档掉到 0.50**（n=4，部分 0.75）
- 末尾组 1.00（n=19）vs 非末尾组 0.9649（n=57）→ `REAL_ABILITY` 成立

## 写这类评估脚本的通用要求

1. 引用一律**正则整体抽取后按集合比较**，不要逐 token/逐字符比对；
2. 编号**不要假设是数字**，也不要用 `int()` 归一化；
3. 留出集必须用训练导出的 `val_split.jsonl`，23 号默认读全量数据（含训练行），
   直接用它报分会虚高（同分布 0.9929 vs 留出 0.9649）。
