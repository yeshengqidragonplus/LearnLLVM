# v5-C1 结论：NAVE 成功于"表示层"，卡在"输出层"（2026-09-19）

## 结果（output_v5c1，94942 条 × 1 epoch，NAVE 开启）

| 维度 | v4-A | v5-C1 | 判读 |
|---|---|---|---|
| 数轴几何 cos(相邻数) | — | **0.9499** | ✅ 值表示形成邻近性 |
| cos(远数) | — | 0.7900 | ✅ 明显更低 |
| cos(Δ1000, Δ10) | — | 0.8867 | ✅ 位权结构一致 |
| proj 范数 | — | 1.1797 | ✅ NAVE 真正激活（从零初始化长出） |

| 后继/加法/数位数 5 位 | 0% | **0%** | ❌ 墙未破 |

## 决定性证据（取位探针）
```
问: 2671 的个位是几?
→ 算法: 个位 = (v div 1) mod 10 = 167 mod 10   ← 算法形式完全正确
→ 答: 7                                         ← 但 2671 被读成 167（丢最高位）
```
**取位算法学会了，但输入数字被截断**。数位数同病：`13819` → `数列 L := 1,3,8,9`（5 位抄成 4 位）。

## 根因：NAVE 只作用于输入嵌入，不改变输出
```
输入侧：NAVE 注入值表示 → 模型"看得见" 2671 的值  ✅
输出侧：模型要生成 "2671" → 逐 token 复制 → 定宽电路  ❌
```
**NAVE 让"每个数字串的值"可见，但不帮助"跨位置复制/对齐"**。

## 设计缺陷（我的错误）
取位数据格式让模型先生成 `理解: 数 v := 94692`——**这一步就是复制**！
模型被训练成"先抄数字串再算"，于是又撞复制墙。
正确做法应是**不生成中间数字串**，直接基于输入（NAVE 增强）输出结果。
