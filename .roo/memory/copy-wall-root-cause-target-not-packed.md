# 复制墙的真正根因：target 没打包（2026-10-21）

`output_decl_expert_v1` 双向 0/24 的原因不是模型容量，而是**数据生成器的遗漏**。

## 现象
- prompt 里是打包形式：`原子包：<|PKG_NAME|> → FARADAY；<|PKG_NUM|> → 286020U`
- 但 target 里是**明文**：`声明一个无符号整型常量 FARADAY，初始值是 286020U。`
- 于是模型必须逐字符复制 `286020U`（7 个字符）+ 复制标识符，这正是 65M 做不到的事：
  值被截断（`5005931L`→`50053L`）、名字从训练分布抽（`energy`→`pos`）。
- 分号语义 12/12 全对，因为那项只需数分号个数，不复制长串。

## 根因位置
`20_prepare_decl_bilingual_v1.py` 的 `Decl.comment`（line 160-165）与
`init_phrase_cn`（line 139）直接用 `self.name` / `self.lit` 拼明文答案。

## 正确做法（用户方案：token filter）
target 也必须用原子包标记：

    target = "声明一个无符号整型常量 <|PKG_NAME|>，初始值是 <|PKG_NUM|>。static const 表示程序运行期间保持不变的静态常量。"

模型只输出静态标记 token（每句话里固定几个），**零字符复制**；程序解包后把标记替换回载荷，
得到与期望完全一致的明文。评估时同样要「先解包再比对」。

## 结论边界
这是数据格式 bug，不是「小模型学不会」。修 target 后需重测才能判断架构是否成立；
在此之前不应把 20% 当作架构负结果。
