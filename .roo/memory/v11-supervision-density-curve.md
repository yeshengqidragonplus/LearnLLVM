# v11 系列：跨类型指代的监督密度曲线（2026-10-30 v11d 训完）

v10 现场测试 T2 跨类型指代 0/30 的根因是训练覆盖缺口（semantic_pick 只在
NUM 上监督过）。v11~v11d 四轮对照把「每个 (类型,编号) 组合的监督次数」
与留出分数的关系定成了单调曲线：

| 每组合监督次数 | 留出 semantic_pick |
|---|---|
| ~1 次（v11b，解耦后） | 0.14 |
| ~2.4 次（v11c） | 0.56 |
| ~5 次（v11d） | **0.91** |

## v11d 配置与结果（2026-10-30）

- 15 epoch / 12,132 条 / lr 3e-4 / seed 42 / 65.48M，`output_probe_v11d`
- 留出 468 条：semantic_pick 2/5/10/20 档 = 0.77/0.97/0.97/0.93；
  distance 10~800 档 0.87~0.93；type_id 四档（k2/k6/open/unseen）全 1.00
- 对照干净：v11c 30ep×6,132 ≈ v11d 15ep×12,132（总样本遍数几乎相同），
  差异纯来自每组合的**不同上下文**监督次数 → 曲线可归因
- 评估报告：`data/probe_v11d_eval.json`（30 号评估器）

## 结论边界

- 0.91 ≠ 机制上限：剩余错误全是「类型对、编号错」（401 选 1 的绑定精度），
  曲线未饱和，继续加密度可收敛。
- 「类型词→类型标记」映射已可靠（type_ok 全 1.00），跨类型指代修复成立。
- v11 初版的教训（同步轮转计数器 = 隐性绑定）见 README 3.11.6；
  多维答案空间监督按组合数算是通用规律：6 类型 × 401 编号 = 2406 组合。
